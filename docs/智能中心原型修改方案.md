# 智能中心原型修改方案

日期：2026-09-14。依据：[需求覆盖核查](智能中心需求覆盖核查.md)。用户已授权先整理方案，再修改代码，本方案落盘后直接实施。

## 目标与范围

保留原生 JavaScript、Python HTTP、SQLite 技术栈和现有前后台布局，补齐完整智能中心在本地可运行的演示流程。真实大模型、生产审批、GIS 算法与统一身份继续作为外部接入边界；本地计算、检索、评测和任务执行必须产生真实可验证的状态变化，不用静态成功提示代替。

不重置现有数据。新增字段采用兼容迁移，保留已有草稿、发布版本、申请、会话及反馈。新增独立演示数据仅使用新的固定标识。

## 修改清单与验收

| 工作包 | 实施方式 | 验收场景 |
| --- | --- | --- |
| 元数据联动 | 资源子类型、来源类型；模板字段定义应用；字典编码/名称/值；关系类型与关联字段；查询字段同义词及字典参与检索，显示标志控制详情 | 字段独有别名发布后可召回；关闭查询标志后不召回；应用模板增加字段；无效关系拒绝保存 |
| 数据清洗与知识生产 | 文本规范化、去重与预览；多文件批次导入并记录逐项结果；统一单文件 200KB 限制；可调整切片长度；本地字符特征向量索引与相似度检索 | 同批成功/失败文件分别显示；较长合法正文可保存；命中相关片段并保留引用版本 |
| 知识图谱 | 结构化实体、类型、关系三元组维护和图形预览；知识权限控制 | 编辑关系后图形更新，非法边端点报错；管理员专属知识不出现在业务回答 |
| 指标计算 | 示例数据表按区域/周期过滤，校验关联字段；安全算术表达式和指标依赖；趋势及区域比较；知识依据绑定 | 修改数据行影响结果；复合指标随基础指标变化；依赖循环、除零、无权资源拒绝计算 |
| 提示词与编排 | 显式输出模板驱动规则回答；有序步骤实际执行并记录输入输出；增加调用知识/指标智能体节点和循环保护 | 删除检索节点后无资源结果；下游智能体输出汇入回答；模板发布前后输出不同 |
| 语料评测与调用 | 预期资源、答案片段、操作序列组成评测集；选择已发布/草稿版本运行并保存差异；JSONL 导出；受控只读 SQL 与本地 API 模板试运行 | 同一评测集对不同版本产生可比结果；失败有原因；任意写 SQL 和非白名单 API 不执行 |
| 长期记忆与接力 | 技能等级、结构化多轮摘要、引用资源/指标与来源；选择旧任务在新会话续接，摘要条件参与新会话 | 延续区域和主题，明确新条件优先；关闭记忆不自动承接；不能续接他人会话 |
| 申请与开放 | 回答中直接打开申请表单；版本化能力调用接口及契约、后台试调用；反馈可更新标注草稿或记忆草稿待确认 | 对话内提交后保持会话；调用返回追踪；改进资产仍遵守草稿发布隔离 |

## 文件组织

- `prototype/capabilities.py`：新增兼容迁移、知识处理、向量检索、指标、图谱、模板执行等领域能力。
- `prototype/server.py`：接入执行编排、评测、批次、权限、记忆与开放接口，保留审批主线。
- `prototype/app.js`、`prototype/style.css`：在已有模块添加工作区、表单、过程追踪和结果展示。
- `prototype/test_capabilities.py`：覆盖关键配置联动、失败边界、权限、兼容性及发布隔离。
- `prototype/README.md`、`prototype/验证记录.md`：更新使用脚本、真实实现范围和验证结果。

## 实施顺序

1. 兼容数据结构与服务端能力。
2. 前后台配置、工作区及对话联动。
3. 领域测试、语法检查，独立测试数据库上的浏览器交互验证。
4. 重启原端口服务，兼容升级已有数据，记录本轮完成情况与仍需外部接入的项目。

## 验证原则

保留原有审批与发布回归；新增测试验证业务结果而非表单存在。浏览器验证使用 agent-browser，覆盖配置保存、批次处理、图谱、对比、评测、接力和接口试调用。原始需求与历史核查文档保持不变，交付时另记修改后的范围。
