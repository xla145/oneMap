## 1. 范围与使用规则

### 1.1 来源

- 主依据：[运营中心原始需求](../img/运营中心.md)，使用附表 `1.6.1—1.6.7` 编号追踪，正文 `5.4.1.1.6` 用于补充解释。同一功能在附表、正文重复出现时只生成一套业务能力。
- 当前实现参考：[四中心功能完善说明](四中心功能完善说明.md)、`prototype/backend/centers.py`、`prototype/frontend/centers.js` 及现有资源、监控管理页面。
- 跨模块设计参考：[智能中心跨模块关联完善说明](智能中心跨模块关联完善说明.md)。

七大业务模块：数据归集、数据质检、数据编目、数据标准、数据建库、数据发布、运行监控。额外增加“运营工作台”作为岗位入口，不计作第八个业务模块。

原文“数据标准管理／数据规范管理”在本清单中统一命名为“数据标准管理”。原始附表的数值列不用于推算页面数量、优先级或工期。

### 1.2 需求属性与优先级

详细清单中的“来源”关联原文要求；岗位划分、页面组织、字段补充、状态拆分、关联提示及验收路径属于本次原型设计建议。未在原文明确的限制、阈值、默认值均不作为已确认业务政策。

| 标记 | 含义 | 原型生成要求 |
| --- | --- | --- |
| P0 | 主流程，优先生成 | 可完成数据接收、质检整改、入库、编目、发布、共享交接、异常处理 |
| P1 | 完整业务覆盖 | 补齐原文管理能力与多场景分支，不能因不是首批而从总清单删除 |
| P2 | 深化配置与运维 | 补齐复杂元模型、数据库／中间件监控等专业页面 |

优先级是建议的生成顺序，不是删减需求或承诺生产实现时间。详细表中的“操作”均要求有相应反馈或后续页面。

### 1.3 两条业务主线

**新增成果数据**：确定标准和目标库 → 下发任务或自主上报 → 登记审核 → 质检 → 整改复检 → 入库 → 编目 → 发布服务 → 交接资源中心。

**已有资产纳管**：登记数源或已有服务 → 采集元数据 → 确认责任单位 → 分类编目 → 建立关联 → 纳入共享与监控。已有服务不强制重新归集或重新发布。

标准、编目、质检可在多个阶段使用；在库数据可以周期质检。不能把所有资源强行放进一条只能前进的线性流程。

## 2. 角色与业务边界

### 2.1 建议岗位

| 角色编号 | 岗位 | 核心权限与工作范围 |
| --- | --- | --- |
| R1 | 数据管理人员 | 维护资产目录、组织归集、审核登记、分派治理、管理标准；按授权区划与单位范围操作 |
| R2 | 数源单位人员 | 接收本单位任务、上报数据、重新提交退回记录、处理本单位整改、查看自己的流转记录 |
| R3 | 质量管理人员 | 维护质检模型与规则、配置任务、查看报告、派单、复检；不能通过修改报告直接制造通过结果 |
| R4 | 数据库与服务管理人员 | 管理目标库和表结构、执行入库、维护发布模型、发布与停用服务 |
| R5 | 运维人员 | 配置监控和巡检、维护告警规则、确认与处理告警、查看趋势和运行日志 |
| R6 | 普通业务用户 | 本人自助质检、本人问题反馈及结果查看；不获得全域数据治理权限 |
| R0 | 平台管理员 | 配置岗位及授权范围、处理平台级配置；原型阶段可用于演示多岗功能 |

以上为目标岗位模型。当前演示身份尚未覆盖所有岗位，生成时可增加明确标注的演示身份；菜单可见性、按钮和数据范围需保持一致，不能只隐藏菜单。

### 2.2 与其他中心的分工

| 管理事项 | 运营中心负责 | 其他模块负责 |
| --- | --- | --- |
| 资源目录 | 技术资产目录、库表／服务元数据、标签和来源关系 | 资源中心：面向使用者的共享目录、共享策略、申请与交付 |
| 数据描述 | 来源、字段类型、坐标系、更新频率、数据关系 | 智能中心：同义词、业务解释、AI 查询语义；引用同一资源记录 |
| 数据服务 | 数据模型、技术接口、图层发布、运行维护 | 资源中心：使用授权；平台网关：统一路由、鉴权及流量策略 |
| 来源应用 | 数据来源系统及归口单位关联 | 应用中心：业务应用构建、审核和上下架；综合集成：统一入口与接入协同 |
| 工具与模型 | 质检／入库／发布任务选择所需工具或模型 | 工具中心：可复用执行能力、版本、接口、调用权限 |
| 待办与通知 | 产生归集、登记、整改、告警任务及处理结果 | 综合集成：汇聚个人待办；统一消息能力：通知投递 |
| 运行观测 | 汇总数据、服务、工具、应用、指标运行情况 | 各业务中心保留专业详情，统一日志与监控记录按对象关联 |

## 3. 菜单与页面目录

建议路由前缀：`/#/admin/operations/`。下表路由是目标设计，不表示当前已存在；生成时为旧入口保留兼容跳转。

一级入口为“运营中心”，内部采用“业务分组 → 页面”，同一对象的状态用标签切换。复杂新增、编辑和详情采用独立页面，不把全部功能塞进一个工作区或长弹窗。

| 分组 | 页面编号与名称 | 建议路由后缀 | 页面形式 |
| --- | --- | --- | --- |
| 运营工作台 | O01 运营总览；O02 我的运营待办 | overview；todos | 指标与任务列表 |
| 数据归集管理 | G01 归集概览；G02 归集任务；G03 归集工单；G04 自助归集；G05 登记审核；G06 数据入库任务 | collection/overview、tasks、orders、self、registrations、imports | 概览、列表、任务详情、分步向导 |
| 数据质检管理 | Q01 质检模型；Q02 质检任务；Q03 质检结果；Q04 数据质量报告；Q05 治理工单；Q06 问题反馈；Q07 线下治理；Q08 自助质检 | quality/models、tasks、results、reports、orders、feedback、offline、self | 列表、规则编辑器、报告、工单详情 |
| 数据编目管理 | C01 来源系统；C02 数源与元数据采集；C03 分类目录；C04 资产编目；C05 资产关系；C06 标签体系；C07 元数据接口 | catalog/systems、sources、directories、assets、relations、tags、apis | 树表、资产详情、关系图、接口说明 |
| 数据标准管理 | S01 标准定义；S02 命名规范；S03 标准变更日志；S04 标准字典；S05 文件管理；S06 元模型 | standards/definitions、naming、changes、dictionaries、files、metamodels | 树表、字段编辑器、版本比较 |
| 数据建库管理 | B01 数据分域与数仓分层；B02 库表设计 | warehouse/domains、tables | 目录树、库表设计页 |
| 数据发布管理 | P01 数据源模型；P02 数据接口；P03 定制接口；P04 图层服务 | publishing/models、apis、custom、layers | 模型编辑、发布向导、服务详情 |

路由约定：列表使用查询参数保存筛选、页码和状态；详情使用 `/对象ID`；新增使用 `/new`；编辑使用 `/对象ID/edit`。上下文跳转附带资产、任务或服务标识，返回列表时恢复原筛选。

## 5. 关键表单与详情规格

本节字段用于生成表单；`*` 为建议必填项，其他字段按场景显示。复杂表单应分步或分区，不要求用户填写与当前模式无关的字段。

### 5.1 G02 归集任务与 G03 报送配置

- 基本信息：任务编号（自动）、任务名称*、接收单位*、报送单位*、联系人*、联系方式*、截止时间*、任务说明*、附件。
- 数据要求：业务主题*、覆盖区域*、数据时间*、成果类型*、关联标准及版本、质检模型、交付格式。
- 接入配置：归集方式*。实时／定时模式显示服务地址*、协议*、认证配置引用、数据范围、抽取频率、增量字段；在线／离线模式显示填报模板、文件及校验结果。
- 任务详情：概况、单位完成情况、工单／批次、附件、时间线。一个任务涉及多个报送单位时，每单位单独显示进度。
- 校验：单位和人员从统一组织选择；截止时间不早于任务发起时间；定时模式必须配置合法周期；凭证不在列表或操作日志显示明文。

### 5.2 G05 登记与 G06 入库向导

1. **选数据**：来源登记／归集批次*、文件*、数据版本、最新质检报告、附件。
2. **选目标**：入库方式*、目标数据库*、数据空间*、目标表*、主键／增量匹配字段（按方式必填）。
3. **字段映射**：源字段、目标字段、两端类型、转换方式、默认值、必填约束；提供样例行预览。
4. **执行确认**：预计数据量、目标范围、质检结论、冲突处理、全量覆盖影响、执行人。
5. **执行结果**：执行编号、进度、成功／失败条数、错误行、起止时间、执行日志、关联资产标识。

质检报告绑定数据版本、标准版本、模型版本。任一发生变化，应提示报告过期并要求重新检查。全量写入在确认页展示受影响表及范围；原型演示写入隔离样例数据，不触及真实库表。

### 5.3 Q01 质检模型与 Q02 任务配置

- 公共：模型名称*、类型*、适用对象*、业务领域、说明、提供方、输入输出要求、版本。
- 第三方：模型地址*、认证引用、输入映射、超时、结果字段映射、联通／测试结果。
- 自定义：模板、规则列表；每条规则包含字段*、规则类型*、参数（按类型必填）、严重程度、问题描述。
- SQL：数据源*、只读语句*、参数、问题记录标识字段、运行范围；预览返回的问题记录。
- 任务：名称*、目标资产／数据包*、模型与版本*、立即／定时*、开始时间、周期、责任人、通知策略。
- 模型详情：定义、试运行、版本、引用任务；任务详情：配置、执行历史、质量趋势、最近报告。

### 5.4 Q05／Q07 治理工单

- 发起：工单名称*、来源类型*、问题报告或线下材料*、关联资源*、责任单位*、处理人*、期限*、问题说明*。

## 6. 状态与流转规则

以下状态为建议原型模型，用于把原文分散描述组织成可操作流程。

| 对象 | 建议状态与主要流转 | 特别规则 |
| --- | --- | --- |
| 归集任务 | 草稿 → 已下发 → 进行中 → 已完成；可终止 | 多单位任务全部满足完成条件后才完成；终止保留原因与已产生记录 |
| 登记／报送审核 | 草稿 → 待审核 → 已通过；待审核 → 已退回 → 重提 | 转审更换处理人并记录原因；下步未处理时允许撤回 |
| 归集执行 | 未开始 → 排队 → 执行中 → 成功／部分失败／失败 | 与审核状态分开；审核通过不自动等于数据已取得 |
| 质检执行 | 待执行 → 执行中 → 已完成／执行失败 | 完成后另显示“质量通过／不通过”；技术执行成功可以发现质量问题 |
| 治理工单 | 待处理 → 处理中 → 待复核 → 已办结；复核不通过 → 已退回 → 重新反馈 | 系统质检问题需复检；操作人、处理人、复核人留痕，建议分岗 |
| 入库任务 | 草稿 → 待校验 → 待执行 → 执行中 → 成功／部分失败／失败 | 当前数据版本与报告不一致时阻止直接入库；已执行记录不可当作草稿删除 |
| 编目状态 | 未编目 → 已编目；可重新挂接 | 变更目录不改变实际数据内容与授权 |
| 标准／模型 | 草稿 → 已发布 → 已停用；发布后修改形成新草稿 | 运行记录绑定执行时版本；历史引用保留 |
| 技术服务 | 草稿 → 测试通过 → 发布中 → 已发布／发布失败；已发布 → 已停用 | 外部登记单列“已登记·待联调”，不直接记为发布成功 |
| 告警事件 | 待确认 → 处理中 → 待验证 → 已关闭；可重新打开 | 指标已恢复不等于人工处置已关闭；记录恢复和关闭两个时间 |

通用流转约束：

1. **待办／已办／办结是工作视图**。待办表示当前需要本人办理；已办表示本人已处理过；办结表示整个流程完成。它们不替代业务状态。
2. **审核退回与执行失败分开**。退回需要修改材料后重提；执行失败需要检查文件、连接或任务配置后重试。
3. **撤回与删除分开**。已发起的流程用撤回或终止，未提交草稿才可直接删除；保留已有业务轨迹。
4. **修订与线上版本分开**。保存草稿不改变现有线上服务；详情展示当前编辑版与生效版。
5. **重复提交控制**。提交／执行中禁用重复操作；重试有独立执行编号，避免重复入库或重复派单。
6. **关联失效可见**。依赖资源、标准、模型或服务不可用时，显示具体对象与原因，提供跳转，不仅弹出“操作失败”。

### 7.3 容易重复建设的边界

- 运营中心的资产编目是技术资产主目录；资源中心组织共享目录与可申请资源。两种目录可映射，不假设必须是同一棵树。
- 技术字典采集、标准字典、AI 枚举别名分别说明用途；基础字典可复用，映射关系可查看。
- 文件管理是任务与标准材料的存储入口，不等同于门户下载资料发布。
- 运行监控复用现有主机监控、日志、告警基础能力；补充业务维度和对象关联，避免并列两套同名监控页面。
- “技术服务发布、共享上架、用户授权、应用上架”分别展示，任何单一动作不能默认替代其余动作。

### 8.2 数据与反馈

1. 搜索支持名称、编号与页面相关业务字段；筛选项有标签，清空可恢复默认；结果为空提供下一步。
2. 列表分页、导出和统计采用相同筛选范围；批量选择明确“本页”或“全部符合条件”。
3. 异步采集、质检、入库和发布展示进度、当前步骤、失败原因、执行历史，不使用固定成功提示。
4. 所有入口具备加载、空、失败、无权限和正常状态。失效对象链接提供解释与返回入口。
5. 演示数据标识“示例”；外部数据源／GIS 引擎／通知通道未配置时显示“待接入／待联调”。若使用模拟执行，结果明确显示“模拟结果”。
6. 下线、全量覆盖、清理目录、删除引用对象等操作先展示对象和影响；不重复要求确认普通查询与草稿保存。
7. 所有状态变化带操作人、时间、说明和关联版本。修改冲突提示刷新后核对，避免覆盖他人的更新。
8. 岗位的数据范围来自统一组织权限；偏好、标签和 AI 记忆不能扩大权限。示例角色的菜单、操作与结果范围保持一致。
