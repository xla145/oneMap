# 对外门户现状评估与优化方案

- 日期：2026-09-15。
- 需求依据：[功能清单与各端范围梳理](功能清单与各端范围梳理.md)，以及 `img/门户页面/` 三张照片的 5.4.1.2 节。
- 评估对象：当前 `prototype/` 的 Python + SQLite + 原生 JavaScript 原型。`bak/` 中的旧多端工程不作为当前已交付能力的依据。
- 方法：阅读当前路由、页面和服务代码，在独立演示数据库启动原型，浏览首页、资源中心、工具与服务、资讯中心，并实测首页搜索跳转。
- 本文为编码前评估，保留当时的现状记录。首轮实施结果见 [对外门户优化实施说明](对外门户优化实施说明.md)。优先级为本次建议，不是原需求规定的等级。

## 1. 结论

现有蓝白门户布局可以保留，资源元数据、申请审核、地图引擎、资讯发布、应用目录和智能助手可以复用。最优先的工作是调整对外门户的信息组织与使用流程。

当前顶层入口和首页内容偏内部业务协同：应用中心、智能中心、工作台、任务督办占据主要位置。对外门户要求的能力服务、办事服务、大美内蒙古尚未形成完整栏目；全局搜索、数据预览和授权后的获取能力也存在差距。

建议将六大公共服务栏目作为主导航，保留智能助手作为辅助入口，将内部工作台放到明确的业务入口下，再逐项补齐数据、工具、办事与内容的使用流程。

## 2. 当前实现与要求对照

“已有”指当前演示原型中存在对应实现，不代表已接入真实业务服务。“未见完整实现”限定于本次检查的当前原型，不推断外部系统是否已有该能力。

| 要求 | 当前情况与依据 | 判断 | 优化方向 |
|---|---|---|---|
| 六大栏目导航 | 实际为首页、资源中心、应用中心、智能中心、资讯中心；定义在 `app.js` 的 `portalNav` | 结构需调整 | 对齐首页、数据服务、能力服务、办事服务、资讯下载、大美内蒙古 |
| 公共服务首页 | 实际首页强调“业务协同”，附带个人工作空间、我的待办、任务督办；由 `platform.js` 的 `home()` 和 `personalView()` 渲染 | 服务对象混合 | 公共内容为首页主体，个人办事进度在登录后的个人服务展示 |
| 全局搜索 | `pc-home-search` 先匹配应用名称，否则启动资源助手；实测搜索“矿业权”进入助手会话 | 未形成综合结果页 | 提供数据、工具、资讯分类结果；保留“向助手提问”独立操作 |
| 首页快捷入口 | 当前为资源中心、应用中心、智能中心、业务工作台 | 与要求不一致 | 改为地图浏览、数据申请、常用工具、办事服务 |
| 政策通知与热门资源 | 当前有效首页主要展示应用、助手和新近资源，资源用数组前几项展示；政策内容在个人区域出现 | 展示和排序机制需补充 | 增加政策通知、推荐资源；区分编辑推荐、最新、热门 |
| 数据目录 | 有名称检索、类型筛选、卡片分页；资源混合库表、图层、工具、知识 | 可复用，分类不完整 | 数据服务以数据集和图层为主，增加主题、地区、单位和共享方式筛选 |
| 数据详情 | 有单位、覆盖范围、坐标系、更新、字段、关联资源和权限说明；当前主要为弹窗 | 可复用 | 建立可直达详情页，完善格式、使用限制、获取方式与调用文档 |
| 在线地图预览 | 资源详情中的图层预览为静态 SVG；独立场景已有 OpenLayers | 两处能力尚未贯通 | 将实际资源图层绑定到地图预览，复用地图引擎 |
| 数据申请审批 | 有申请清单、用途期限、逐项审核、授权状态；授权后主要打开示例内容 | 流程基础已有 | 补数据包获取、下载记录、API 凭证与到期状态 |
| OGC / REST 服务 | 已有智能体接口、网关等基础，但不能据此认定已完成对外图层发布和密钥全流程 | 未见完整数据服务交付链路 | 设计服务登记、授权、地址、密钥、调用统计和实际服务对接 |
| 能力服务 | `tools` 页面展示语义解读、指标分析、知识问答、场景提问、个性化服务 | 与空间工具要求不同 | 补空间工具市场及输入、执行、结果页面；AI 服务作为辅助分类 |
| 空间分析 | 独立地图支持查看、选区和近似量算；`spatial.py` 对缓冲、叠加面积等问题明确不支持 | 部分基础可复用 | 分别补缓冲、转换、叠加、选址和合规分析，不能以工具卡片代替实现 |
| 办事服务 | 有应用目录、业务事项表单、流程、办件详情和工作台 | 有底座，公众入口未成形 | 建立查询、公示、指南、咨询等公众服务栏目，对接具体业务来源 |
| 资讯下载 | 已有政策、动态、标准、培训四类，支持搜索、阅读、推荐和 TXT 正文下载 | 最接近要求 | 统一栏目名，补原始文件、PDF 预览、视频与附件管理 |
| 大美内蒙古 | 当前有耕地等地图场景，但未见五个公众专题的独立栏目及完整内容 | 需补建 | 复用地图与内容能力，建设五个专题及运营配置 |
| 门户后台 | 已有资源、知识、审批、用户、应用和智能资产管理 | 可复用，公共门户运营项需补 | 补首页配置、公众服务内容、专题配置、文件、密钥和公众反馈 |
| 公众身份 | 当前进入页面使用演示业务身份；有身份管理原型 | 需区分使用场景 | 补游客、普通用户、企业/机构与管理员的页面状态和服务端权限 |

## 3. 推荐的信息架构

| 主导航 | 二级内容 | 现有功能处置 |
|---|---|---|
| 首页 | 综合搜索、快捷服务、政策通知、推荐数据、常用能力、特色专题 | 重组当前首页，保留整体品牌和蓝白视觉 |
| 数据服务 | 数据目录、图层服务、资源详情、地图预览、申请获取、开发者说明 | 复用资源中心；工具和资讯从主分类中分流，关联入口保留 |
| 能力服务 | 基础空间工具、选址与合规审查、共享模型、智能辅助、使用教程 | 复用部分应用目录和助手入口，新增真正的空间工具操作页 |
| 办事服务 | 不动产查询、审批进度、矿业权查询、规划公示、地价、指南、咨询留言 | 复用事项与办件底座，补公众查询和反馈流程 |
| 资讯下载 | 政策法规、行业动态、技术标准、培训资源 | 复用当前资讯中心，补文件能力 |
| 大美内蒙古 | 自然地理、空间规划、能源基地、社会公共服务、生态屏障 | 新建专题聚合与详情，复用地图、媒体和发布能力 |

全局辅助入口建议为：智能助手、登录/注册、个人中心。个人中心承载我的数据申请、我的授权/密钥、我的办事、我的咨询、收藏和消息。

应用中心保留为应用资源目录，按对外开放范围将相应应用挂入能力服务、办事服务或专题。内部流程办理、数字会商、任务督办和内部管理入口保留在内部业务空间。功能迁移先明确受众和可见性，避免将已有能力直接删除。

“大美内蒙古”暂沿用清单与正文标题；照片首页中的“壮美内蒙古”作为文案待确认项。

## 4. 首页如何调整

### 推荐的页面顺序

1. 顶部品牌、六大导航、智能助手和个人服务入口。
2. 首屏介绍服务对象及用途，突出全局搜索；建议主文案为“自然资源一张图，让数据与服务触手可及”，副文案明确“查数据、用工具、办事情、看内蒙古”。文案为设计建议。
3. 四个快捷入口：地图浏览、数据申请、常用工具、办事服务。应在常见桌面首屏或紧接首屏的位置可见。
4. 政策法规/通知区：有来源、发布日期和详情链接；如采用滚动展示，应允许暂停或手动切换。
5. 数据推荐：主题分类、最新发布、热门资源。热门有统计依据，编辑选择则明确显示“推荐”。
6. 常用能力与便民办事：直达高频工具和具体查询，减少反复进入分类页。
7. 大美内蒙古：五个专题入口，以真实内容与地图预览展示地方特色。
8. 资讯下载与使用帮助，底部放主办信息、联系方式等已确认内容。

### 当前页面应重点减轻的内容

- 当前首屏装饰图占用较多纵向空间。保留蓝白品牌，压缩装饰区域，让用户更快看到搜索与四个直接服务入口。
- “应用中心”“智能中心”不再分别占据公共首页的大段核心区域，可合并为常用能力与智能辅助入口。
- “林晓的工作空间”、内部任务督办、会商工作概览移到个人或内部工作台。对外首页登录后可以展示精简的“我的申请/我的办事”提示。
- 资源卡片优先呈现用途、地区、来源、更新日期和获取方式；同义词、结构化关系等技术信息放在详情的高级区域。

## 5. 优先补齐四条使用流程

### 5.1 搜索到具体结果

输入关键词 → 综合结果页 → 按数据/工具/资讯切换 → 查看详情 → 申请、使用或下载。

建议先聚合现有已发布且当前访问者可见的资源、工具和资讯，按关键词相关性展示，并保留分页、结果数量和无结果提示。查询词与分类进入 URL，返回结果页时保留条件。智能问答通过单独按钮携带当前关键词和资源上下文进入，避免普通检索自动创建会话。

### 5.2 数据申请到实际获取

目录 → 详情/地图预览 → 填用途期限 → 提交 → 后台审核 → 下载或获取授权调用方式 → 查看有效期和记录。

复用现有申请清单和逐项审核，重点补齐授权后的出口。区分“公开可用”“需申请”“办理中”“已授权”“已过期”等状态。数据预览和正式下载权限可以不同，但应由服务端分别判断。

地图预览绑定具体资源与图层，不以相同示意图展示所有资源。下载项显示格式、大小、版本；API 详情显示地址、协议、参数、错误说明、使用期限和文档。地图底图浏览、业务图层预览、OGC 服务发布是不同交付项。

### 5.3 工具选择到结果查看

选择工具 → 阅读适用范围/示例 → 上传或绘制输入 → 填参数 → 执行 → 地图和表格展示结果 → 导出/查看历史。

建议先补坐标转换、面积量算，再补缓冲和叠加分析，最后接选址与合规审查的业务规则。每种工具明确输入坐标系、参数单位、输出类型和错误状态。地图引擎的投影转换不等同于覆盖所有业务坐标系的转换服务。

项目合规结论必须由正式规则和空间数据支撑。原型阶段可展示明确标注的示例流程，不能将现有人工“合规/不合规”选择框或预置分析结果当作自动审查完成。

### 5.4 公众办事到进度与反馈

选择事项 → 看指南/查询条件 → 查询或进入对应系统 → 看结果与进度 → 提交咨询/意见 → 查询回复。

办事入口分清“在线查询”“外部办理”“公示反馈”三种类型，按钮表达真实行为。项目审批流程原型可以复用，但需按具体服务增加查询字段、结果结构和来源接口；不动产、矿业权、地价不能共用一个泛化的业务表单就算完成。

## 6. 资讯与特色专题的补充设计

### 资讯下载

当前四类资讯保留，优先完善正式附件：文件名称、格式、大小、版本、发布日期、下载次数和权限；支持 PDF 预览、原文件下载及视频播放。TXT 正文导出保留为辅助操作。

发布内容与 AI 知识材料可引用同一来源，但应分别标记“对外公开展示”和“可供知识检索”。内部业务指南或知识片段不应仅因知识库已发布就自动进入公众资讯栏目。

### 大美内蒙古

建设一个专题聚合页和可配置的专题详情模板。每个专题组合简介、地图图层、图表/指标、图片视频和延伸阅读；按专题需要选择区块，避免五个页面仅替换标题与图片。

| 专题 | 推荐内容组织（设计建议） |
|---|---|
| 自然地理风光 | 草原、森林、沙漠、河湖分布，地点介绍与风光媒体 |
| 国土空间规划 | 规划格局、成果摘要、图集阅读、所在地查询入口 |
| 重要能源保障基地 | 煤炭、稀土、风能、太阳能专题图及开发规划介绍 |
| 社会公众服务 | 便民站点、地灾避险场所，分类与位置查询 |
| 北疆安全生态屏障 | 重大生态工程分布、治理措施、成效图文与统计 |

后台维护专题名称、排序、封面、说明、图层引用、媒体、图表数据、关联资源和发布状态。原型采用示例内容时应明确标注；实际内容由业务方提供或确认。

## 7. 后台如何承接

建议先复用已有管理能力并按角色组织菜单；是否拆成独立后台应用再根据账号和部署边界决定。

| 后台分组 | 可复用基础 | 需要增加或核实 |
|---|---|---|
| 门户配置 | 当前页面框架与个人首页配置经验 | 公共首页区块、导航、通知、推荐和链接配置；个人配置不能替代公共运营配置 |
| 数据与授权 | 资源元数据、草稿发布、申请审核 | 公开范围、数据包、图层服务绑定、API 密钥、有效期和调用统计 |
| 能力管理 | 应用注册、工具资源、智能体发布 | 工具输入输出规范、执行服务绑定、示例、教程、上下架和版本 |
| 办事管理 | 事项模型、表单、办件、流程 | 公众查询服务配置、办事指南、公示期限、意见受理回复和咨询记录 |
| 内容与专题 | 知识/资讯草稿、发布、停用 | 原始附件、媒体、专题区块、公众发布范围和首页推荐 |
| 用户与角色 | 当前身份与角色原型 | 游客/个人/企业机构的流程与权限、注册审核和正式认证接入 |
| 日志与统计 | 当前调用记录、审核记录等 | 门户访问、下载、工具运行、热门排序指标与服务状态监控 |

每个新增页面都要有明确内容来源。例如专题卡片由专题管理发布，首页通知由资讯/通知管理发布；不能只将文字写死在前端。

## 8. 代码实施位置与复用原则

当前工程使用原生 JavaScript，不需要为了门户调整引入 Vue 或重写技术栈。

| 位置 | 当前职责 | 建议修改 |
|---|---|---|
| `prototype/app.js`：`portalNav`、`portalShell()` | 导航、门户公共布局 | 六大栏目、登录状态、辅助入口与面包屑 |
| `prototype/frontend/platform.js`：`home()`、`render()` | 当前实际首页与应用/办事/地图页面 | 重组对外首页；明确内部工作空间入口 |
| 同文件：`pc-home-search` 提交处理 | 应用命中直达，否则进入助手 | 替换为综合搜索路由；智能问答独立触发 |
| `prototype/frontend/workspaces.js`：`personalView()` | 个人工作空间与督办等内容 | 从公众首页主体迁出，按身份保留相应个人服务 |
| `prototype/app.js`：`renderCatalog()`、`resourceDetail()`、`previewResource()` | 目录、详情弹窗、示例预览 | 数据服务筛选、详情路由、地图预览与获取出口 |
| `prototype/frontend/map.js` | OpenLayers 地图场景 | 抽取可复用的资源预览和工具地图承载能力 |
| `prototype/frontend/news.js` | 四类资讯、搜索推荐、TXT 导出 | 更名为资讯下载，增加附件和媒体展示 |
| `prototype/frontend/portal-blue.css`、`platform.css`、`news.css` | 当前页面样式 | 沿用蓝白基调，调整首屏、六栏导航、卡片和移动布局 |
| `prototype/server.py` 及领域/存储模块 | 本地 API 与业务状态 | 公共可见性、搜索聚合、文件、密钥、专题和公众反馈等服务 |

特别注意：`app.js` 中仍有 `renderPortalHome()`，但当前 `renderPage()` 优先调用 `platformUI.render()`；实际 `home` 路由由 `platform.js` 接管。只修改旧首页函数不会改变当前用户看到的首页。建议梳理保留一个明确的首页渲染入口，避免后续再次出现维护错位。

新增公众功能建议拆成独立模块，避免继续向 `app.js` 和 `platform.js` 堆叠所有页面。旧 `catalog`、`knowledge`、`tools` 等链接保留兼容跳转，并正确映射新导航高亮。数据模型采用增量迁移，保留既有资源、申请、会话和发布记录。

## 9. 实施优先级

### P0：先把门户入口和主要行为对齐

- 六大栏目及有效路由；明确应用目录、内部工作台、智能助手的入口位置。
- 重组首页，调整四个快捷入口，增加通知、资源和特色专题的展示位置。
- 建立综合搜索结果页，解决搜索直接进入助手的问题。
- 建立数据详情路由，将资源图层预览接入现有地图引擎。
