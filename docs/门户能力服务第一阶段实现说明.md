# 门户能力服务第一阶段实现说明

- 更新日期：2026-09-15。
- 对应方案：[门户能力服务功能清单及实现方案](门户能力服务功能清单及实现方案.md) 阶段 A。
- 当前交付：可运行的本地空间分析原型，使用真实几何运算和明确标注的人工示例数据。

## 1. 使用入口

- 核查工作台：`http://127.0.0.1:5190/#/front/capabilities/compliance`。
- 叠加与多地块工具：`http://127.0.0.1:5190/#/front/capabilities/overlay`。
- 原有 5191 预览端口同步可用。

核查操作：点击“载入示例”，然后“运行核查”。示例包含两块地块，一块发现冲突，一块未发现所选规则冲突。也可上传 GeoJSON、粘贴闭合坐标数组或在地图上绘制，再校验和运行。结果区可定位地块、下载报告与明细；历史任务可载入输入重新运行。

## 2. 本次已实现

| 功能 | 交付内容 |
|---|---|
| 地块输入 | GeoJSON 上传、Polygon/MultiPolygon、孔洞、多地块、坐标粘贴、地图绘制；绘制替换当前输入 |
| 输入校验 | 显式选择 WGS84 或 Web Mercator；有限坐标、范围、闭合、自相交、空几何、面积、重复 ID、数量与顶点上限检查 |
| 输入保存 | 保存原始输入文本/对象、源 CRS、标准化几何、创建时间与所属用户；输入和任务分开保存 |
| 管控核查 | 示例生态红线、永久基本农田与规划允许建设范围，固定运行三项规则 |
| 计算结果 | 逐地块、逐规则空间关系、面积和占比；同一地块各规则冲突面积融合去重 |
| 结论语义 | 未发现所选规则冲突、发现冲突、需人工复核、无法判定；边界接触单列复核 |
| 完整性检查 | 缺失、过期、未授权、超出数据完整覆盖范围时无法判定；不以零面积冒充已完成核查 |
| 任务管理 | SQLite 持久化，后台 worker 领取计算；排队、运行、成功、部分完成、失败、取消；创建任务幂等；历史重算生成新任务 |
| 权限 | 所有输入、任务、结果和报告绑定当前演示身份，其他身份不能查询、取消或导出 |
| 地图展示 | 输入、示例约束与冲突范围分色，支持完整多多边形和孔洞，地块卡片定位 |
| 报告 | HTML 可打印报告，包含冲突示意图、逐项明细、去重面积与输入/规则/数据快照；CSV 明细、GeoJSON 冲突几何 |
| 基础空间工具补充 | 相交、差集、融合、多地块面积、面缓冲及 GeoJSON 导出；保留原坐标转换、点缓冲与简单面积工具 |

“相交”和“差集”要求正好两个地块，按 A、B 输入顺序计算；“融合”和“面积”针对全部地块融合去重。空交集返回空结果，不生成虚构图斑。面缓冲使用局部等距投影，面积统计使用 EPSG:6933 等积投影。

## 3. 数据与结果边界

示例版本 `synthetic-2026-09-v1`，覆盖经度 111.5～112、纬度 40.5～41。数据由程序人工构造，既不是正式红线/基本农田数据，也不来自国家级或自治区级共享模型平台。

示例规则为：与示例红线或基本农田发生面积交叠则发现冲突；位于示例规划允许范围外则发现冲突；只有边界接触时提示人工复核。0.01 平方米用于本原型的数值容差，不是政策允许占用阈值。

“未发现所选规则冲突”仅说明本次完整执行的三项示例检查结果，不等于行政审批通过。正式业务仍需接入合法可用的管控矢量、数据版本、规则依据、认证及正式报告要求。

本阶段限制为单次输入最多 10 MB、100 个地块、50000 个顶点；HTTP JSON 请求体上限 11000000 字节，接近上限的文本转义可能使请求超过上限。面缓冲距离大于 0 且不超过 100000 米，输入经纬跨度各不超过 2 度。暂不支持 SHP/GPKG/CAD、测绘基准转换、线缓冲和批量坐标文件映射。

## 4. 实现位置与接口

| 文件 | 职责 |
|---|---|
| `prototype/analysis_engine.py` | 示例数据与规则、几何校验、投影、核查与基础空间运算 |
| `prototype/analysis_jobs.py` | 独立输入/任务表、归属检查、幂等与后台任务状态 |
| `prototype/analysis_reports.py` | 从已存结果快照生成 HTML、CSV、GeoJSON |
| `prototype/frontend/analysis-workbench.js` | 上传、绘制、运行、状态轮询、结果、导出与历史界面 |
| `prototype/frontend/map.js` | 完整 GeoJSON 结果绘制和定位，保留旧地图接口 |
| `prototype/server.py` | `/api/action` 接入分析操作，在全局状态锁之外执行 |
| `prototype/frontend/public-portal.js`、`public-tools.js`、`public-portal.css` | 门户入口、工具状态和响应式布局 |
| `prototype/requirements.txt` | Shapely 与 pyproj 依赖 |

本阶段共用现有 `/api/action`，动作包括：

- `analysis.catalog`：示例数据、规则、样例与版本。
- `analysis.input`：校验保存输入，返回 inputId 与标准化地块。
- `analysis.create`：按 inputId 创建任务，校验请求幂等键。
- `analysis.list`：当前用户最近 50 个任务。
- `analysis.get`：所属任务状态及已存结果。
- `analysis.cancel`：将排队或运行任务标记为取消；取消后不写入结果。
- `analysis.export`：从任务结果导出 HTML、CSV、GeoJSON。
- `analysis.spatial`：执行相交、差集、融合、面积或面缓冲。

新增 `analysis_inputs`、`analysis_jobs` 两张表，不改变已有业务表结构，不把分析结果塞入全量 bootstrap。计算在独立于主状态锁的后台线程中执行，SQLite 事务只负责领取和状态落库；多个预览进程可原子领取不同任务。简单空间工具为同步调用，同样不持有全局状态锁。

当前取消阻止结果写回，并不强制中断已经进入 GEOS 的函数。启动后的 worker 会将超过 120 秒的遗留运行任务标记失败，允许用户以新任务重算；尚未实现生产级进程强制超时、心跳租约续期和资源队列。分析文件以数据库私有记录保存，不公开静态文件 URL。

## 5. 启动与验证

在项目根目录执行：

```sh
python3 -m venv prototype/.venv
prototype/.venv/bin/pip install -r prototype/requirements.txt
prototype/.venv/bin/python prototype/server.py --port 5190
```

测试：

```sh
prototype/.venv/bin/python -m unittest discover -s prototype -p 'test_*.py'
node prototype/test_public_tools.mjs
node prototype/test_workspaces.mjs
```

浏览器测试使用独立数据库，避免创建演示任务污染用户业务数据：

```sh
prototype/.venv/bin/python prototype/server.py --port 5217 --host 127.0.0.1 --db /tmp/onemap-analysis-qa.sqlite3
DEMO_QA_URL=http://127.0.0.1:5217 python3 prototype/check_analysis_browser.py
DEMO_QA_URL=http://127.0.0.1:5217 python3 prototype/check_public_portal.py
```

本次后端验证通过 112 项（新增分析测试 9 项）；基础工具与工作台 JavaScript 测试通过。浏览器专项通过 11 项，涵盖样例计算、真实文件上传、三个导出操作、无效几何、空间运算与 1440/1024/390 像素布局。另完成原门户 63 项响应式路由回归，无浏览器错误。专项结果见 `prototype/analysis-browser-checks.json`，截图见 `prototype/screenshots/analysis-desktop.png` 与 `analysis-mobile.png`。

预览更新前数据库已备份到 `prototype/data/backups/before-analysis-20260915-172858.sqlite3`。
