# 智能体中心地图协同实现方案

> 当前状态：按用户要求已撤下智能助手地图协同界面，恢复对话方式。以下保留本轮实现与规划记录，暂不作为当前页面使用说明。


日期：2026-09-15  
状态：已完成首期演示实现：OpenLayers 地图工作台、范围查询、结果上图、多轮追问与历史恢复。具体交付与限制见 [智能体地图协同实现说明](智能体地图协同实现说明.md)。下文保留完整规划，P1/P2 及生产数据接入尚未实施。

## 1. 建设目标

将智能体中心建设为自然资源业务的地图分析工作台，让用户完成“选择智能体 → 确定空间范围 → 提问分析 → 结果上图 → 查看依据 → 继续追问”的完整流程。

保留门户主导航中的“智能中心”，专区标题使用“智能体中心”。智能体广场承担发现与选择，智能分析工作台承担实际使用。应用中心继续负责专题场景与业务应用的发布和进入；两处复用同一套地图、会话及结果能力。

本方案默认继续迭代当前 Python + SQLite + 原生 JavaScript 原型。首期以本地示例数据形成可运行闭环；真实空间服务和大模型接入另设验收条件。

## 2. 当前实现与缺口

| 范围 | 当前实现依据 | 本轮需要补齐 |
| --- | --- | --- |
| 智能中心 | `frontend/platform.js` 的 `intelligence()` 提供问题输入、助手卡片与服务入口 | 增加业务专题、地图能力标签、最近分析任务和统一工作台入口 |
| 对话分析 | `app.js` 支持会话、区域与时间条件、引用、指标、执行追踪及反馈 | 同屏地图、空间上下文、结构化结果与地图联动 |
| 地图场景 | `frontend/map.js` 已替换为 OpenLayers，并复用指定 demo 的天地图配置与行政区数据；支持缩放、平移、图斑点击、绘制近似量算、视图保存与释放 | 选区查询、分析结果覆盖物、结果要素定位 |
| 场景与助手 | 场景提问携带业务上下文进入助手，图斑点击仅更新属性区 | 把所选图斑、图层与范围传入会话，在地图内完成对话 |
| 数据与分析 | 已有资源权限、指标、知识、规则执行及版本机制 | 明确几何数据契约、空间筛选工具、结果快照和权限复核 |

当前底图与图斑属于本地二维演示，外部空间查询和几何服务仅有登记入口。原有按区域的指标统计不能直接解释为用户圈选范围内的精确统计。

## 3. 页面组织

### 3.1 智能体中心首页

首页突出可完成的业务任务：地图找资源、耕地保护分析、地灾巡查辅助、项目辅助审查。提供统一提问入口、专题筛选、智能体卡片和最近分析记录。

智能体卡片展示名称、用途、示例问题、适用区域、依赖数据和能力标签，例如“地图检索”“指标统计”“政策问答”。只有已具备空间工具的智能体显示地图分析能力；纯知识助手仍可在同一工作台使用并收起地图。

### 3.2 智能分析工作台

桌面采用左侧对话、中央地图、右侧详情的布局。左侧约 360px，地图自适应，右侧约 320px 且默认收起；结果表格在地图下方按需展开。图层目录作为地图内的折叠面板，避免常驻第四栏挤占画布。

```text
顶部：返回智能体中心｜当前智能体｜区域｜时间｜历史任务
┌────────────────┬────────────────────────┬───────────────┐
│ 对话与分析       │ 地图画布                │ 详情抽屉       │
│ 当前范围摘要     │ 图层目录 / 选择与绘制    │ 图斑属性       │
│ 问答、引用与进度 │ 选区 / 高亮 / 分析结果   │ 数据与政策依据 │
│ 快捷追问与输入框 │ 图例、比例与范围提示     │ 统计口径       │
│                ├────────────────────────┤               │
│                │ 结果列表 / 统计图表      │               │
└────────────────┴────────────────────────┴───────────────┘
```

小屏幕使用“对话 / 地图 / 结果”标签切换，共享同一任务状态。地图初始化失败时给出重试入口；支持纯知识任务继续使用。

建议沿用 `/#/front/intelligence`、`/#/front/agents` 和 `/#/front/assistant` 路由，在助手内部扩展工作台，避免创建第二套会话系统。现有地图场景中的智能辅助入口调用相同的会话组件。

## 4. 核心交互规则

### 4.1 地图向对话提供上下文

支持行政区选择、点击图斑、框选和绘制多边形。选完后展示范围名称、对象数量及“使用此范围提问”操作，提交时保存空间快照。

范围模式明确区分：行政区、所选对象、自定义范围。切换时替换活动范围；如果需要按行政区裁剪选区，界面显式显示两者交集。纯粹平移或缩放地图不会改变查询范围。

对话输入区持续显示区域、时间、活动范围和参与分析的图层。用户提问指定其他区域时，先提示范围冲突并提供切换入口；缺少分析年份、图层或指标口径时先补条件。

### 4.2 对话驱动地图

回答返回结构化结果：文字结论、资源列表、空间要素、统计结果、依据与可执行地图操作。前端根据白名单动作执行定位、显示图层、突出选区、添加结果图层和清理本轮结果。

地图动作只使用经过服务端授权的资源与结果标识，不能执行回答中的任意 JavaScript 或服务地址。推荐图层通过“添加到地图”按钮启用；分析产生的临时图层可自动展示并支持撤销。

### 4.3 地图、列表和结论联动

点击结果行定位并高亮对应要素；点击地图要素选中结果行并打开属性；点击统计分组筛选对应结果。列表与地图共享同一结果集合，展示完整数量、已加载数量及分页状态。

缺少几何的资源仍可展示在列表中，并说明无法定位。没有结果、没有权限和数据源失败使用不同状态，避免把服务失败显示成“零风险”或“没有图斑”。

### 4.4 多轮与历史

“只看高风险”“换成 2025 年”等追问复用上一轮明确范围。每轮结果保存自己的条件、资源版本、工具参数和统计口径；新一轮改变范围不会改写旧结果。

历史任务恢复对话、区域、图层与选区，重新检查当前权限。过期授权不得通过旧结果快照恢复几何和受限属性。会话切换、取消任务和快速连续提问时，旧请求不能覆盖当前地图。

## 5. 首期业务场景与范围

| 优先级 | 场景 | 完整流程 | 能力边界 |
| --- | --- | --- | --- |
| P0 | 地图找资源 | 选择包头市 → 提问查找地灾相关资源 → 返回资源卡片 → 已授权图层上图 → 点击查看属性 | 目录检索与空间要素查询分别返回；受限资源走既有申请流程 |
| P0 | 耕地保护分析 | 选择示例区域/图斑 → 提问统计 → 展示数量、面积口径、图表与高亮 → 追问指定年份 | 完全选中图斑可汇总面积属性；部分相交只能统计相交图斑数量，精确交叠面积待几何工具支持 |
| P1 | 地灾巡查辅助 | 选择巡查范围 → 筛选隐患点/记录 → 按已有风险字段分组 → 定位与查看记录 | 缺少风险字段时不生成风险等级；不能宣称预测灾害 |
| P1 | 项目辅助审查 | 从项目进入 → 加载项目范围与约束图层 → 执行相交分析 → 查看命中对象、面积及政策引用 | 依赖有效项目几何和约束数据；结论用于辅助复核 |
| P2 | 扩展分析 | 缓冲区、跨期变化、专题渲染、分析报告与成果导出 | 在真实几何计算与数据版本能力就绪后实施 |

首期交付 P0 两条闭环及通用工作台。P1/P2 不以预置文案或随机图斑冒充分析结果。

## 6. 实现设计

### 6.1 前端模块

新增智能工作台模块、空间上下文状态模块、结果面板模块和地图动作执行模块。复用已有会话、知识引用、指标卡片、资源申请与反馈组件。

扩展地图适配接口：`setLayers`、`fitBounds`、`selectFeatures`、`setSelection`、`setResultLayers`、`getViewState`、`restoreViewState`、`destroy`；事件包含要素点击、范围选择和视图变化。图层开关增量更新，不再每次重建地图导致视图丢失。底图加载失败应允许重新请求。

已确认采用 OpenLayers，当前已替换本地 SVG 引擎，并按用户指定复用 `内蒙古一张图demo` 的天地图影像/矢量/地形配置和行政区数据。原 demo 使用 Leaflet；当前使用 OpenLayers 承载这些地图资源。在线瓦片失败时使用本地行政区底图。后续在同一适配层扩展地图与智能体联动，真实业务图层仍需明确服务协议、坐标系和鉴权方式。

### 6.2 空间上下文与结果契约

| 对象 | 建议字段 | 约束 |
| --- | --- | --- |
| `spatialContext` | `mode`、`regionCode`、`sceneId`、`layerIds`、`featureRefs`、`geometry`、`crs`、`period`、`contextRevision` | 要素引用含资源/图层 ID 与要素 ID；区域使用编码；每轮冻结 |
| `analysisResult` | `id`、`sessionId`、`messageId`、`status`、`summary`、`featureRefs`、`statistics`、`citations`、`mapActions`、`dataVersions` | 标注完整/部分/失败结果、缺失数据、统计方法与单位 |
| `mapState` | `extent`、`basemapId`、`visibleLayerIds`、`selectedFeatureRefs`、`resultLayerIds` | 展示状态与查询范围分离，不作为权限依据 |

本地规范统一经度、纬度顺序，几何对象显式携带 CRS。外部服务的坐标轴约定由适配层转换；不直接把 EPSG:4490 改标签当作 EPSG:4326。绘制几何校验闭环、有效顶点数、自相交、范围及大小。

扩展现有智能体调用请求，增加可选 `spatialContext`；旧请求继续有效。响应保留现有文字、引用和追踪，增加可选 `analysisResult`。详细几何通过已授权结果查询按需读取，避免把大体积要素全集写入每条消息。

### 6.3 服务端工具执行

首期提供受控工具：行政区定位、授权图层查询、选区相交筛选、属性汇总、结果组装。选区筛选应使用有效几何算法；包围盒只可用于候选预筛，不能代替多边形相交结论。

空间计算使用经过验证的几何库或空间服务，不在对话模型中手算。首期若引入 Shapely 等依赖，明确安装与版本要求；经纬度面积需另用合适的投影或测地计算，不能使用平面经纬度面积直接换算公顷。依赖不可用时禁用相应工具并显示原因。

执行顺序为条件解析、参数校验、权限过滤、空间查询、统计/知识查询、结果组装。现有规则执行器先承载示例问题；后续大模型只负责意图与工具参数建议，工具调用仍由服务端校验。

首期小规模本地任务可同步执行。真实远程调用或长计算应在数据库写锁之外执行，按任务 ID 持久化状态；取消、超时、重试和迟到结果都校验任务与上下文版本。

### 6.4 数据保存与权限

沿用当前 SQLite 增量迁移机制，新增任务结果/空间快照存储，旧会话没有空间字段时使用兼容默认值。避免反复向会话写入整套图层几何。

服务端对图层、要素、区域、字段、统计和导出统一授权；客户端提交的几何、图层 ID、旧结果 ID 均需重新校验。资源申请通过后刷新权限，再允许加载受限图层。历史记录始终只对有权用户开放。

## 7. 后台配置补充

在现有智能体管理中增加“地图能力”配置页签：默认场景、允许图层、可调用空间工具、输入条件、输出类型、推荐问题和执行限制。关联既有知识、指标与语料资产，不另建重复目录。

调试区增加地图与对话预览，能看到实际输入范围、授权后数据范围、工具参数、结果与失败原因。发布时校验图层与工具可用性，并冻结绑定版本。普通业务用户不能通过提问启用管理员未发布的工具。

## 8. 实施顺序

1. 统一空间上下文、结果契约与示例数据；明确区域编码、要素主键、坐标系及面积口径。
2. 完成地图工作台布局、选区交互、地图状态保存和场景入口复用。
3. 接通地图资源检索、授权图层展示、结果列表与地图双向联动。
4. 接通耕地示例统计、多轮追问、历史恢复及后台配置。
5. 完成权限与异常回归、移动端和局域网 HTTP 浏览器验证，再扩展地灾与项目分析。

各阶段以可演示流程验收。正式服务接入前需落实地图协议、坐标系、鉴权方式、数据样例以及智能体运行接口，再评估具体工期。

## 9. 验收标准

- 从智能体中心进入工作台，在同一页面完成提问、查看地图和结果，无需跳出会话。
- 点击图斑、框选、多边形选区均形成可见查询条件；仅平移地图不会更改条件。
- 至少用相离、相交、包含、边界接触及无效多边形样例验证选区计算，明确边界接触的纳入规则。
- 两个 P0 场景使用确定的示例数据，地图要素、列表数量、统计口径和引用一致。
- 结果行与地图要素双向定位；地图图层切换保留缩放与平移状态。
- 多轮切换时间/范围不会篡改旧结果；历史恢复和跨场景接续保持明确的上下文。
- 未授权、权限过期和越区请求均不能获取受限要素或统计，错误提示不泄漏受限属性。
- 空结果、缺数据、工具不支持、超时与服务失败可区分；失败任务不会输出成功分析结论。
- 保持既有资源申请、知识引用、指标、会话与后台发布流程可用；浏览器回归使用独立数据库。
- 在 `localhost` 和局域网 HTTP 均可初始化并完成选区与提问；移动端可切换地图与对话。

## 10. 评审建议

建议按“智能体中心入口 + 地图对话工作台 + 两个 P0 场景”启动，采用左侧对话、中央地图、右侧按需详情的页面方向。真实业务地图服务可在数据接口明确后替换本地地图适配器。

待评审重点为：首期业务专题是否优先耕地/地灾；是否已有指定地图平台与服务协议；项目审查是否有可用项目红线与约束图层。未明确前按本文示例数据范围规划，不承诺正式业务分析精度。
