# 综合集成原型重构实现方案

- 日期：2026-09-16
- 文档状态：已按本方案实施，见[三域重构实现说明](综合集成三域重构实现说明.md)
- 方案编写阶段交付：仅新增本方案；随后经确认实施，变更和验收结果见实现说明
- 需求依据：[综合集成原始需求](../img/运营中心/综合集成.md)
- 现状依据：当前 `prototype` 页面、导航、权限和数据接口；[上一轮实现说明](综合集成后台管理流程实现说明.md)仅作为现状记录

## 1. 修改方向

**将综合集成调整为“一张图成果、数字资源、个人工作台”三个主要使用入口，将发布、接入、监测、授权集中到管理员使用的“集成配置”。**

原文的核心是“统一认证、三域集成”，服务于自然资源工作者日常看成果、找资源、办事情。界面应首先让用户完成这些工作，再提供相应配置和维护能力。

本方案保留成果工作区位于后台的既有归属。这里的后台同时承载内部业务使用和平台管理，两类用户通过不同菜单权限进入，不再把“使用后台界面”等同于“拥有平台管理权限”。数字资源和个人工作台也统一到内部后台框架，形成连续的工作空间；公众门户保持独立。

### 1.1 三个主要入口各自负责什么

| 入口名称 | 对应原始需求 | 主要用户 | 用户应完成的事情 |
| --- | --- | --- | --- |
| 一张图成果 | 一张图成果综合集成 | 管理层、查询分析人员 | 浏览图层、查询地块、使用空间分析、访问工具和业务场景、查看成果使用情况 |
| 数字资源 | 数字资源综合集成 | 数据使用人员、开发人员 | 统一搜索数据、服务、工具、知识、智能体和应用，查看详情、申请或进入使用 |
| 个人工作台 | 工作任务综合集成 | 内部工作人员 | 查看本人待办和提醒、进入业务办理、打开收藏应用和工具 |
| 集成配置 | 门户通用功能及各类对接要求 | 平台管理员 | 配置展示、维护接入、查看运行问题、管理授权与租户 |

表中的前三项对应原文三域；第四项是配套管理入口。本方案不再增加独立“综合集成首页”或新的运行驾驶舱。

### 1.2 本轮交付范围

本轮优先完成页面归属、信息组织、使用流程、数据口径和权限边界调整，复用已有可运行能力。

完整三维分析、正式八类专题、时间序列数据、真实跨系统认证与任务接口、全平台多租户等仍属于原始建设范围，但不以这次界面重构宣称完成。具体依赖见第9节。

## 2. 当前问题与修改决定

| 当前情况 | 对用户的影响 | 本次决定 |
| --- | --- | --- |
| 运行总览置于综合集成首位，突出配置缺失、同步失败、人工核对 | 用户首先看到维护事项，难以理解综合集成的业务用途 | 撤下主入口位置，移入“集成配置 → 运行维护” |
| 一张图成果在后台，数字资源门户和个人工作台在前台框架 | 三域之间切换割裂，容易与公众门户混淆 | 统一内部框架和主导航，兼容原有链接 |
| 系统接入、任务协同、运行监测、权限租户占据大量左侧菜单 | 支撑功能压过使用功能 | 收拢为一个“集成配置”，内部按管理对象组织 |
| “任务协同”的主要内容是同步批次和办理核对 | 个人工作任务与管理员运维记录容易混淆 | 主入口展示“我的待办”；同步与核对下沉到来源系统详情 |
| 个人工作台包含治理工单、租户工作空间等多个并列标签 | 常用应用、工具和待办的主线被稀释 | 租户管理移入集成配置；治理任务提供归口入口，不另扩展一套治理管理 |
| 成果编排主要维护主题、部门、区域、手册 | 名称容易使人误以为可编辑完整地图场景 | 改称“展示分类”，复杂场景编辑仍归应用中心 |
| 已有主记录在不同中心展示，维护责任不直观 | 容易在综合集成重复建资源或配置场景 | 展示和收藏共用原对象ID；详情明确来源中心和维护入口 |
| 管理员模式下 `centers.todos` 包含所有外部待办 | 直接搬用页面会把全平台任务显示成“我的待办” | 建立明确的本人工作数据返回结构，管理员个人工作台也只看本人任务 |
| 管理员模式下门户内容包含草稿 | 直接将前台页面放到后台可能把未发布内容展示出来 | 使用页始终读取已发布且对当前用户生效的内容；草稿仅在配置与预览页读取 |

## 3. 目标导航与页面归属

### 3.1 左侧导航

```text
综合集成
├─ 一张图成果
├─ 数字资源
├─ 个人工作台
└─ 集成配置            仅平台管理员可见
```

约束：

1. 主菜单只保留上述四项，普通内部用户最多看到前三项。
2. “一张图成果”根据既有成果查看授权显示；没有成果权限不影响数字资源和个人工作台的独立使用权限。
3. “集成配置”置于末尾，不默认展开一棵维护功能树。
4. 页面标题、左侧菜单和面包屑使用同一份导航定义。
5. 用户进入综合集成的统一入口时，优先恢复上次可访问的三域页面；没有记录时进入个人工作台。权限撤回后重新选择可访问页面。
6. 现有平台级“管理工作台”仍服务于全平台管理，不复制其内容到综合集成。
7. 角色化默认首页、岗位模板等增强能力暂不新增，避免再引入一层首页配置。

### 3.2 推荐路由

以下为拟实施的地址，并非当前已上线页面。

| 页面 | 推荐地址 | 说明 |
| --- | --- | --- |
| 一张图成果 | `/#/admin/integration-results` | 保留现有地址 |
| 数字资源 | `/#/admin/integration-resources` | 复用现有综合门户和目录能力 |
| 个人工作台 | `/#/admin/integration-workbench` | 与已有业务流程工作台 `/#/front/workbench` 区分 |
| 集成配置 | `/#/admin/integration-settings` | 默认展示门户展示配置 |

成果页内部视图使用 `?tab=map/tools/scenes/usage`；个人工作台的更多待办、消息、收藏列表使用参数保存当前视图与筛选条件。配置详情使用 `section`、`tab`、`system`、`id` 等参数定位。

不创建“工作门户”“综合工作区”“综合集成管理首页”等新的同义入口。

### 3.3 与五大中心的边界

| 对象或操作 | 综合集成承担什么 | 原中心继续承担什么 |
| --- | --- | --- |
| 数据、服务 | 搜索、分类展示、详情和申请入口 | 资源中心的目录、授权、交付；运营中心的归集与治理 |
| 工具 | 工具箱展示、收藏、进入使用 | 工具中心的登记、审核、发布和能力维护 |
| 应用、场景 | 按八类主题发现和访问 | 应用中心的登记、场景编辑、发布和业务流程 |
| 知识、智能体 | 统一检索、详情及使用入口 | 智能中心的内容、能力和版本管理 |
| 工作任务 | 汇聚本人任务、提醒和穿透办理 | 来源业务系统的办理规则与业务状态 |
| 登录、消息通道 | 关联已有客户端和消息服务 | 现有认证、身份和消息总线管理能力 |

五大中心快捷导航按权限呈现：有管理权限时进入管理入口，只有使用权限时进入对应使用目录。没有可访问目标的入口不显示，避免用户点击后才被拒绝。

## 4. 三个主要页面的实现方案

### 4.1 一张图成果

**定位：以地图为核心的成果使用页面。**

```text
一张图成果
[空间图层] [工具箱] [应用场景] [成果使用概况]

空间图层视图：
图层目录与筛选       地图及常用操作       属性与查询结果
```

#### 保留与调整

- 保留当前二维地图、已授权图层、透明度、行政区定位、属性查看、范围查询、查询历史和放大工作区。
- 默认进入“空间图层”，地图占据主要展示面积。
- 将“八类场景”标签改为“应用场景”，在页面内部按需求中的八类主题组织。
- 工具箱展示分类、检索、详情、手册和使用入口；不混入工具审核与发布操作。
- 应用场景展示主题、关联应用和已有系统入口；不在此创建业务系统主记录。
- “成果使用概况”承接原文的图层、工具、场景集成监测，按对象展示规模、来源、接入与使用情况；有权限的管理员可进一步进入运行维护详情。
- 成果使用统计与运行维护分开：前者回答“有什么、谁在用”，后者回答“哪里异常、如何处理”。统计数据复用同一来源，避免重复计数。

#### 交互与状态

- 用户没有分析权限时，保留成果查看，分析操作不开放；服务端继续校验。
- 无可用场景、无权限、查询未命中、服务异常分别显示对应状态。
- 尚未提供的三维、时序、专题能力不放置可点击但无实际结果的按钮。
- 从成果页打开工具或场景时，提供返回成果页的入口；仅在目标支持时传递已授权的场景、图层或地块上下文，不强行把所有工具嵌入地图。
- 跳转后返回应恢复当前场景、目录筛选、已启用图层和视角；恢复前重新核验权限。

### 4.2 数字资源

**定位：内部统一资源发现入口，综合搜索优先。**

```text
数字资源
[综合搜索：数据 / 服务 / 工具 / 知识 / 智能体 / 应用]
热门搜索词（不超过5个）

六类资源数量与分类入口
五大中心快捷入口（按权限显示）

最新资源                     热门资源
成果宣传 / 公告 / Banner（有已发布内容时展示）
```

#### 页面调整

- 复用 `home()`、`catalog()` 的搜索和目录能力，将搜索移到页面首要位置。
- 宣传图和Banner不再占据搜索前的大面积首屏；保留原文要求的宣传、动态与热门资源区域。
- 默认呈现资源入口与摘要。执行搜索或点击分类后进入同页结果视图，保留搜索词、类型、主题、部门和页码。
- 六类数量遵循当前用户的目录可见范围；点击数字进入相同口径的分类列表。
- 每张卡片明确资源名称、类型、来源、更新信息和可用操作，避免所有对象都只提供含义模糊的“详情 / 使用”。
- 不在普通资源卡片上放编排、发布、停用等管理按钮；有管理权限者在详情中看到“到原中心维护”。

#### 操作按资源类型区分

| 类型 | 用户操作 |
| --- | --- |
| 数据、图层服务、API服务 | 查看详情；按授权状态申请、预览或进入使用 |
| 工具 | 查看详情、查看手册、收藏、打开工具 |
| 应用场景 | 查看详情、收藏、进入应用或场景 |
| 知识 | 阅读内容、查看来源；下载按已有授权规则执行 |
| 智能体 | 查看介绍、进入使用 |

#### 统计和内容口径

- 优先使用已存在的聚合热词与成功调用统计；原型无足够记录时显示空状态，不编造排行。
- 个人搜索历史与平台热门搜索词明确区分。
- 展示页只读取已发布内容，按人群、部门、租户和有效时间过滤；管理员也遵循使用页口径。
- 一揽子申请复用现有申请链路，只聚合支持申请的资源；不同类型对象不强行放入同一审批。
- 外部系统入口、工具入口和应用主对象保持引用关系，同一主对象不因在多个位置展示就重复统计。

### 4.3 个人工作台

**定位：用户进入后直接知道“我要做什么、常用什么”。**

```text
个人工作台                                      [个人设置]
待办总数   正常   逾期   预警   未读消息

我的待办（优先展示需处理任务）       我的应用
任务 / 来源 / 时间 / 状态 / 办理    我的工具
[查看全部待办]                      [管理收藏]

消息提醒与公告
```

#### 页面调整

- 默认展示上述工作桌面，不再用一排标签代替首页内容。
- “我的待办”“我的应用”“我的工具”直接可见；更多记录进入有地址的列表视图。
- 待办按来源系统、办理状态、时效状态筛选，支持标题检索。
- 任务显示来源、发起时间、截止时间、状态和办理入口；入口缺失时给出明确说明。
- 收藏复用现有对象ID、分组和排序，与数字资源、成果工具箱中的收藏双向一致。
- 消息中心合并呈现本人审批通知、系统消息和公告；类型、未读状态可筛选，不再增加平行的“任务消息管理”页面。
- 个人设置收纳排序、分组、看板显示、刷新频率、消息开关和免打扰设置。

#### 本人数据口径

- 本地流程任务依据当前处理人/有效委托等已有业务规则确定；外部任务依据接收人映射确定。
- 管理员打开个人工作台也只看到自己的任务；所有人的任务只在具有权限的来源系统管理视图出现。
- 待办总数按现有状态归一后统计，待办、在办、已挂起属于未完成；已办和已办结归入已办。
- 正常、逾期、预警仅在未完成任务内分类，同一任务只占一个时效分类；没有截止时间归正常，不能把已办任务计入正常待办。
- 卡片数量与点击后的列表使用同一套服务端筛选，不能在浏览器分别拼装口径。

#### 移出和下沉

- “租户工作空间”的管理能力移至集成配置的权限与租户区域；需要使用本级租户资源的人员通过有权限的资源或业务入口访问。
- 本人治理工单可提供运营中心归口入口；若统一列入待办，应使用稳定的来源标识并去重，整改、审核等操作继续由运营中心办理。
- 不显示接收人映射、JSON导入、同步批次、失败归档、人工核对等维护操作。

## 5. 集成配置如何收拢

集成配置仅保留四个内部分类。操作尽量围绕门户内容或接入对象进入详情，不再为每种辅助动作增加左侧菜单。

```text
集成配置
[门户展示] [系统接入] [运行维护] [权限与租户]
```

| 分类 | 页面内内容 | 组织方式 |
| --- | --- | --- |
| 门户展示 | 基础展示、导航、Banner、宣传、动态、公告、展示分类 | 按页面区域选择内容，继续保留草稿、发布、预览和历史版本 |
| 系统接入 | 内部系统、国家节点、纵向节点、横向平台 | 按接入类型筛选对象，进入对象详情查看所需能力和状态 |
| 运行维护 | 接入状态、使用统计、异常、执行记录 | 承接现有运维总览与监测，异常下钻到具体来源对象或批次 |
| 权限与租户 | 成果查看/分析授权、查询范围策略、三级租户与成员授权 | 复用既有权限记录，与资源授权及平台身份管理保持清晰边界 |

### 5.1 来源系统详情

内部系统详情建议组织为：

```text
系统名称、归口单位、负责人、接入能力和当前状态
[基本信息] [认证关联] [待办接入（适用时）] [运行记录]
```

- 八个业务系统展示入口与单点登录关联；厅门户网站保留仅入口的接入方式。
- 仅两个原定待办来源展示待办接入配置。
- 接收人/状态映射、版本同步、失败重试、人工处置和核对历史放入“待办接入/运行记录”。
- 接入计划改为对象详情内的实施进展，复用已有记录；不再作为独立主导航。
- 统一登录接入、消息总线保留唯一维护页面，从详情关联进入，不复制配置表单和主数据。

### 5.2 不同对接类型保留业务差异

| 对接类型 | 详情需要表达的重点 |
| --- | --- |
| 国家节点 | 统一命名、域名、用户体系、国家基础服务使用、省级服务注册 |
| 纵向节点 | 自治区—盟市—旗县层级关系、目录和服务交换、访问入口、对应租户 |
| 横向平台 | 对接单位、用户互认范围、服务共享范围、交换对象 |

可以复用列表和执行记录组件，但不能只用同一个“端点＋导入导出”表单代表全部需求。协议未确定的项目标记待对接，保留依赖说明；本轮不虚构可运行接口。

## 6. 已有功能保留、迁移与收口清单

| 现有功能 | 调整后的归属 | 处理方式 |
| --- | --- | --- |
| 一张图成果、二维查询 | 一张图成果 | 保留并整理页面内部视图 |
| 数字资源门户 | 数字资源 | 移入内部框架，重排搜索与展示优先级 |
| 个人工作台 | 个人工作台 | 改为桌面布局，修正本人数据与统计 |
| 运行总览 | 集成配置 / 运行维护 / 接入状态 | 保留统计和下钻，下沉入口 |
| 门户展示、公告通知 | 集成配置 / 门户展示 | 合并管理入口，不合并不同发布对象 |
| 成果编排 | 集成配置 / 门户展示 / 展示分类 | 更名；仅维护展示归类，不接管场景编辑 |
| 内部系统、国家对接、纵向交换、横向联动 | 集成配置 / 系统接入 | 用接入类型组织对象，保留类型差异 |
| 接入计划 | 接入对象详情 / 实施进展 | 保留记录与编辑，撤下独立菜单 |
| 待办同步、接收人和状态映射 | 来源系统详情 / 待办接入 | 保留已验证的版本和重试机制 |
| 办理核对 | 来源系统详情 / 运行记录 | 更名为“人工状态核对”，作为辅助操作 |
| 异常处理、失败归档 | 集成配置 / 运行维护及对象运行记录 | 保留问题来源、处理记录和历史 |
| 使用统计 | 成果使用概况＋运行维护 | 共用统计源，按使用者权限返回摘要或明细 |
| 成果使用授权、面积限制、三级租户 | 集成配置 / 权限与租户 | 保留数据，面积策略从门户视觉设置中移出 |
| 统一登录接入、消息总线 | 现有支撑管理页 | 唯一维护入口，综合集成通过对象详情关联 |
| 公众门户首页配置 | 现有门户运营 | 保持独立，不并入内部门户配置 |

此次重构不删除已有系统、资源、收藏、任务、同步批次、人工核对、计划、租户、授权或发布版本记录。

## 7. 技术实现与数据边界

### 7.1 权限调整

目前后端以后台模式和管理角色作为入口判断，同时成果授权允许部分业务用户进入后台。新增内部资源和工作台后，应增加明确的内部工作空间准入，避免通过扩大平台管理员角色实现页面访问。

| 权限 | 来源/实现原则 | 可访问范围 |
| --- | --- | --- |
| 内部工作空间准入 | 在既有身份管理中维护明确标志，要求账号有效 | 数字资源、本人工作台及有权访问的中心使用入口 |
| 成果查看 | 复用现有 `resultAccess.view` | 成果浏览及被授权的使用统计摘要 |
| 成果分析 | 复用现有 `resultAccess.analyze`，依赖查看 | 现有空间查询与分析入口 |
| 集成配置管理 | 保持现有平台管理员校验 | 草稿、发布、接入维护、运行明细与授权管理 |

迁移时只为明确的现有内部演示身份及管理身份设置内部准入；不因账号角色为“业务用户”就自动给所有公众注册账号开放后台。既有成果查看授权保留有效访问能力。账号停用、授权撤回后，导航、页面和接口均重新校验。

### 7.2 使用数据与管理数据分开返回

拟增加或明确以下返回结构，命名在实施时与现有接口风格保持一致：

| 数据视图 | 主要内容 | 必须遵循的边界 |
| --- | --- | --- |
| `resourcePortal` | 已发布门户内容、可见目录、分类统计、热词与动态 | 不因管理员身份混入草稿、受限目录或管理明细 |
| `personalWorkbench` | 本人任务、同口径统计、消息、收藏、个人设置 | 不直接复用管理模式下的全量 `centers.todos` |
| `resultUsage` | 当前可见范围内的成果规模和使用摘要 | 不直接向普通成果用户开放完整管理监测接口 |
| `integrationManagement` | 接入对象、草稿、同步批次、问题与管理配置 | 继续由服务端执行管理权限校验 |

实现上优先复用 `integration_plus.task_rows()`、现有目录可见性、已发布快照、消息归属和权限函数。客户端传入的页面类型只能选择返回结构，不能作为授权依据。

对资源、任务、内容和统计范围的区分必须在服务端完成。避免只靠移除按钮或前端过滤修正数据边界。

### 7.3 路由兼容

| 旧地址 | 兼容策略 |
| --- | --- |
| `/#/front/integrated-portal`、`/#/front/internal-home` | 迁至数字资源，执行内部准入校验；不足权限时给出明确提示和公众门户返回入口 |
| `/#/front/integrated-workbench` | 迁至个人工作台，保留可识别的视图、筛选和对象参数 |
| `/#/front/integration-results` | 延续现有成果后台重定向与权限检查 |
| `/#/admin/center-integration?tab=overview/monitor/exceptions` | 定位集成配置的运行维护对应视图 |
| `…?tab=presentation/announcements/placement` | 定位门户展示的对应区域 |
| `…?tab=systems/national/vertical/horizontal` | 定位系统接入的对应类型 |
| `…?tab=tasks/receipts&system=…` | 定位来源系统的待办接入或运行记录；无来源参数时显示待办接入系统列表 |
| `…?tab=plans` | 定位系统接入中的实施进展列表，记录可进入关联对象 |
| `…?tab=access/tenants` | 定位权限与租户的对应视图 |
| 外部业务系统、原中心详情地址 | 保留原目标，只补充支持范围内的返回上下文 |

重定向使用替换历史记录的方式，避免浏览器返回在新旧地址之间循环。只接收已知参数和站内返回地址，不采用任意跳转目标。

## 8. 实施顺序与验收

### 8.1 分步实施

| 阶段 | 优先级 | 实施内容 | 完成标志 |
| --- | --- | --- | --- |
| A：入口与数据边界 | P0 | 明确内部准入、三域使用数据与管理数据；配置新路由及旧地址映射 | 内部用户可访问对应页面，公众身份不被意外提升；管理数据不混入使用页 |
| B：主导航与配置收拢 | P0 | 上线三个主入口和末尾配置入口；迁移15个管理视图 | 左侧结构收敛，旧功能从新归属可找到，旧链接可定位 |
| C：数字资源与个人桌面 | P0 | 搜索优先、发布态内容、本人待办、收藏和消息桌面、同口径统计 | 用户能完成找资源和办本人任务的完整路径 |
| D：成果页面整理 | P0 | 保留地图能力，统一工具/场景访问，补使用概况与返回上下文 | 成果查看和分析可用，维护操作不挤占地图 |
| E：回归与切换 | P0 | 身份、发布、任务、导航、地图、租户及移动端回归；备份数据再切换 | 页面与接口验收通过，主记录与历史记录保留 |

阶段C和D都属于本轮必要交付，不能仅完成菜单重排就称为重构完成。

### 8.2 可核验的验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| GI-R01 | 主导航 | 综合集成下只出现三域入口和有权限时的集成配置；不再出现独立接入计划、人工核对等主菜单 |
| GI-R02 | 页面一致性 | 三域使用同一内部框架，标题与面包屑一致；不混用公众门户布局 |
| GI-R03 | 身份准入 | 内部普通用户可进入自己的工作台；公众身份不能借新地址访问内部功能；成果和管理授权仍单独控制 |
| GI-R04 | 发布隔离 | 管理员修改未发布Banner或公告后，在数字资源使用页仍看到原已发布内容；预览页能看到草稿 |
| GI-R05 | 资源搜索 | 按资源类型检索、详情、申请/使用、收藏及返回的状态可保持；资源数量与分类列表一致 |
| GI-R06 | 个人任务 | 两个用户互不看到对方任务；管理员本人工作台也不显示其他用户外部待办 |
| GI-R07 | 任务统计 | 正常、逾期、预警不重复计数，已办不混入待办；点击卡片后的列表与数字一致 |
| GI-R08 | 收藏和消息 | 从资源/成果页收藏后出现在本人工作台；取消同步消失；消息已读状态与免打扰继续有效 |
| GI-R09 | 成果能力 | 图层、查询、历史及返回恢复可用；查看权限不能调用分析接口；撤权后缓存视角不能恢复受限图层 |
| GI-R10 | 管理可达 | 平台管理员可从配置入口定位系统、映射、失败批次、人工核对和接入计划；没有丢失上一轮能力 |
| GI-R11 | 对接真实性 | 文件导入、配置完整、人工核对和外部联通分别表达，不以界面迁移改变状态含义 |
| GI-R12 | 地址兼容 | 旧三域及管理地址均到达对应页面，带来源系统的链接保留范围；刷新和前进后退无循环 |
| GI-R13 | 数据保留 | 用户、资源、授权、收藏、任务、批次、计划、租户和发布版本主标识及历史记录迁移前后可核对 |
| GI-R14 | 响应式与状态 | 桌面和390px宽度可完成主要操作；无数据、无权限、加载、失败状态可识别，页面无整体横向溢出 |

回归重点是在导航重组之后，仍能走通“资源申请”“本人待办办理跳转”“门户草稿发布”“地图授权查询”“同步失败重试”“租户授权撤回”等既有流程，而不是只检查菜单文字。

## 9. 原始需求覆盖与后续依赖

| 原始需求范围 | 本方案的归属 | 本轮处理及后续依赖 |
| --- | --- | --- |
| 1.1.1 成果集成 | 一张图成果 | 整理地图、工具、场景及使用概况；完整四维目录、三维、时序及正式八专题仍需专门深化和正式数据 |
| 1.1.2 数字资源集成 | 数字资源 | 搜索、分类统计、中心导航、宣传、动态、热门资源回归同一入口；更深入跨中心检索能力按数据条件迭代 |
| 1.1.3 工作任务集成 | 个人工作台 | 本人任务、应用、工具、消息成为页面主体；两个来源系统的实时同步与回传仍需真实接口 |
| 1.1.4 门户通用功能 | 共用认证＋集成配置＋个人设置 | 复用登录和发布机制，明确使用配置归属；生产SSO、MFA及完整可视化编辑能力另行对接 |
| 1.1.5 内部系统集成 | 数字资源/成果中的使用入口＋系统接入配置 | 保留九系统及不同接入级别，不复制系统主记录；外部服务需联调 |
| 1.1.6 国家级对接 | 系统接入 / 国家节点 | 保留命名、域名、用户、基础服务与注册要求；需国家标准和测试环境 |
| 1.1.7 纵向贯通 | 系统接入 / 纵向节点＋权限与租户 | 保留三级结构与现有局部隔离；全平台租户隔离不能靠菜单重组实现 |
| 1.1.8 横向联动 | 系统接入 / 横向平台 | 按对接单位表达身份与空间服务共享范围；需对方接口和授权 |

原文没有要求“接入计划、人工状态核对、失败归档”成为主要产品栏目。这些作为已实现的辅助维护能力保留在对象详情，后续不继续围绕它们扩展主导航。
