## 1. 需求原文与范围

### 1.1 六项原始要求

以下规范了 API 等原文录入字符，未改变需求含义。

| 原编号 | 模块 | 原文要求 |
|---|---|---|
| 2.3.1 | 基础空间分析工具 | 提供缓冲区分析、面积量算、坐标转换、叠加分析等在线工具，用户输入参数即可运行 |
| 2.3.2 | 项目选址及合规性审查工具 | 用户上传地块坐标或范围，自动分析是否符合规划、生态红线、基本农田等管控要求，生成审查报告 |
| 2.3.3 | 能力共享市场 | 分类展示国家级和自治区级共享的分析模型及工具，支持在线体验和参数配置 |
| 2.3.4 | 工具调用 API | 将常用工具封装为 API 服务，供外部系统集成调用，需申请密钥 |
| 2.3.5 | 能力服务申请与管理 | 管理员对工具服务进行注册、上下架、版本管理、调用统计和权限分配 |
| 2.3.6 | 使用教程 | 每个能力服务提供详细说明文档、参数示例和操作视频 |

照片正文另明确：输入可为“地块坐标或规划数据”；工具应满足企业、科研机构及开发者的分析需求；管控对象包含生态红线、永久基本农田。

### 1.2 建设范围解释

本模块应包含四个相互关联的部分：

- 门户前台：发现工具/模型、查看说明、申请、在线体验、查看结果和下载报告。
- 分析工作台：数据上传、地图绘制、参数填写、任务执行、冲突查看、结果比较。
- 能力管理后台：工具与模型登记发布、规则和数据绑定、教程、授权、运行与调用管理。
- 后端执行服务：数据校验、空间运算、规则评估、异步任务、结果和报告、模型适配与 API。

“项目选址”先按**已有候选地块的适宜性核查与比较**设计。全域自动寻找候选地块、智能优化选址、机器学习预测属于可选扩展，原文没有明确算法和指标，不纳入首阶段必交范围。

内部“项目辅助审查”的表单、人工审批和合规标记可作为后续人工复核入口，但不能替代自动空间分析。智能助手可解释结果与引用依据，不能代替空间计算和正式规则判定。

## 2. 当前实现状态

状态定义：“部分实现”为已有可运行子集；“可复用基础”为其他模块存在相关能力但本模块尚未打通；“未实现”为没有对应完整功能；“仅入口”为页面说明，不含执行能力。

|---|---|---|
| 能力服务栏目 | 部分实现 | 有能力卡片、基础工具详情、智能辅助和共享工具资源目录 |
| 坐标转换 | 部分实现 | 仅 WGS84 经纬度与 Web Mercator 数值互转，无正式测绘基准转换和多格式批量转换 |
| 面积量算 | 部分实现 | 可粘贴坐标/单 Polygon 或绘制，计算球面近似面积；不支持孔洞、MultiPolygon 和批量规划数据 |
| 缓冲区 | 部分实现 | 仅点缓冲，球面近似，距离大于 0 至 100000 米；未实现线、面缓冲 |
| 叠加分析 | 仅入口 | `overlay` 标记为 `available:false` |
| 项目选址、合规审查 | 仅入口 | `compliance` 标记为 `available:false`，没有自动规则计算和审查报告 |
| 地块/规划文件上传 | 未实现 | 现有量算输入不等于文件上传、字段映射、CRS 校验和数据入库 |
| 管控数据参与计算 | 可复用基础 | 地图已有授权示例图层；尚无正式红线/基本农田数据及可追溯规则计算链路 |
| 国家级/自治区级模型市场 | 未实现 | 当前目录没有经来源核验的分级模型、版本、适配器和在线任务管理 |
| 模型在线体验与参数表单 | 未实现 | 尚无由模型输入定义驱动的统一体验流程 |
| 工具 API 与密钥 | 可复用基础 | 已有本地 API 和网关演示；本模块无工具任务 API、密钥申请授权和撤销闭环 |
| 工具/模型运营管理 | 可复用基础 | 已有资源和应用注册发布；当前三种基础计算工具仍由前端数组定义，不是可管理的统一工具目录 |
| 教程、示例、视频 | 部分实现 | 有简短说明和少量默认参数，无逐工具完整教程与视频管理 |

不能将“地图能显示图斑”“目录存在工具卡片”“前端有运行按钮”统计为高级分析能力已完成。

### 4.2 高级分析工作台布局

- 顶部：项目名称、分析类型、保存输入、提交任务。
- 左侧：输入地块列表、文件校验结果、管控图层、规则选择。
- 中部：OpenLayers 地图，展示输入、管控与结果图层。
- 右侧：参数、适用条件、数据/规则版本和逐项结论。
- 底部或结果页：地块明细、冲突统计、执行信息和报告导出。

流程固定为“输入 → 校验 → 确认数据与规则 → 执行 → 查看结果”。缺少必要数据时展示具体原因，不能跳过后直接输出通过。

### 4.3 后台页面

建议将“能力服务管理”作为单独业务分组，包含工具模型、分析图层、规则集、教程样例、能力授权、执行任务与调用统计。公共门户现有专题/办事内容管理继续保留，不把所有分析配置塞入通用内容编辑器。

资源、版本和规则选择使用名称、来源、更新时间与状态展示；底层标识用于追溯，不要求普通用户填写数据库 ID 或脚本。

## 5. 空间分析与规则判定

### 5.1 输入与计算准备

1. 保存原始输入和文件摘要，生成所属用户/组织的输入记录。
2. 校验文件格式、要素数量、几何类型、拓扑、字段及 CRS。
3. GeoJSON 的标准经纬度输入按明确约定处理；非标准坐标必须显式指定源 CRS，不静默猜测。
4. 将输入与分析图层转换到约定的计算 CRS。`pyproj` 建议明确采用 X/Y 顺序；记录实际转换参数和精度条件。
5. 分析面积与距离使用适用于该区域的批准投影/测算方法，不用 Web Mercator 面积充当业务面积。内蒙古跨多个投影分带，不能一律套用同一带号。
6. 保存标准化几何；如需修复，先展示变化并得到使用者确认，保留修复记录。

原型第一阶段使用已知 CRS、范围小且可独立验证的人工示例数据。正式测绘数据涉及基准转换时，需采用业务确认的转换方法与参数。

### 5.2 空间关系与面积计算

对每个输入地块分别执行：

- 先通过空间索引筛选候选要素，再计算精确空间关系。
- 相交返回具体交叠几何、原地块 ID、管控要素 ID 和面积。
- 同一检查项内先按需要融合交叠面，再计算占用面积，避免重叠管控要素重复累加。
- 跨红线/基本农田等类别分别出具结果；综合涉及面积如需统计，应对全部冲突面求并集，不能直接相加。
- 交叠比例＝去重交叠面积÷有效地块面积。零面积地块在输入校验阶段拒绝。
- “仅边界接触”和“存在面积交叠”分别记录；是否构成业务问题由相应规则定义。
- 展示值可舍入，规则比较使用约定精度的计算值；微小面容差有单位和依据，不能用任意阈值把冲突消掉。

规划符合性还需判断输入用途与规划分区的适用关系，不能只检查是否落在一张图层上。

### 5.3 规则定义

建议规则包含：规则名称/版本、适用区域与项目类型、所需图层版本、空间谓词、阈值与单位、依据及生效时间、命中提示、结果等级、数据缺失时的处理方式。

原型示例规则可定义“与示例红线出现面积交叠时标记冲突，待业务复核”，但必须标注为示例规则，不能包装成正式政策判定。

正式规则使用受限的结构化定义，例如空间谓词、阈值和枚举条件；不允许通过网页任意提交可执行 Python/SQL 脚本。

### 5.4 结果语义

| 结果状态 | 判定条件 | 页面含义 |
|---|---|---|
| 未发现所选规则冲突 | 所有必需检查完成，数据覆盖有效，已执行规则均未命中冲突 | 仅说明本次输入、数据和规则下的结果，不等于行政审批通过 |
| 发现冲突 | 至少一项已确认规则命中冲突 | 显示冲突位置、面积、依据和建议处理 |
| 需人工复核 | 条件存在例外、用途含义不确定或规则明确要求人工判定 | 显示需复核项，不自动赋予通过结论 |
| 无法判定 | 缺失/过期/无权限数据、覆盖不完整、必要计算失败或规则不适用 | 明确阻塞原因与下一步操作 |

如果既发现冲突又有未完成检查，应同时显示“已发现冲突”和“检查不完整”，保留所有未判定项，不能将其归为完整合规或完整审查。

### 5.5 报告与追溯

报告应包含任务编号、执行时间、输入地块与摘要、输入/计算 CRS、工具和模型版本、数据来源及版本、规则依据、逐项结果、冲突地图、统计口径、未完成项和适用限制。

报告与地图、明细表从同一份结果快照生成。第一阶段交付可打印 HTML 报告与 GeoJSON/CSV；正式 PDF 在后续接入服务端渲染并做版式验证。历史报告不因模型升级或图层更新被覆盖。

## 6. 模型市场及调用机制

### 6.1 分开记录模型来源和执行方式

| 维度 | 取值建议 | 说明 |
|---|---|---|
| 来源层级 | 国家级、自治区级、本地示例 | 依据提供方信息标注，不以名称或人工随意填写冒充权威来源 |
| 来源核验 | 待核验、已核验 | 已核验需保留提供单位、目录标识、接入依据和核验记录 |
| 执行方式 | 内置算法、本地服务、外部 API、外链体验 | 执行方式与来源层级互相独立 |
| 发布状态 | 草稿、待发布、已发布、已停用 | 未发布版本不得出现在前台可执行目录 |
| 运行状态 | 可运行、需授权、连接异常、待接入 | 不把“已登记”视为“可在线体验” |

没有真实国家级/自治区级服务资料时，目录可以预留分类；演示模型应标注为“本地示例”。真实模型可登记来源元数据并显示待接入，但不能用本地固定结果伪装远程模型调用。

### 6.2 模型执行适配

所有执行器统一约定四部分：输入定义、提交任务、获取状态、标准化结果。外部供应商采用同步或异步 API，均由后端适配，浏览器不直接持有服务端凭证。

输入定义至少包括字段名、显示名称、类型、必填、默认值、单位、范围、枚举、支持的文件与几何类型。输出约定地图几何、指标表、结果说明和文件链接；不认识的输出类型明确提示不支持。

外链体验只提供经核验的跳转与回跳说明，不计为已经完成门户内嵌计算。服务离线、超时或返回无效结果时应显示真实失败，不回退为模拟“成功”。

### 6.3 使用授权

能力使用权限与其依赖的数据权限分开检查。具备工具权限不自动获得红线数据、业务原始数据或报告下载权限。

任务执行前检查一次，结果查询与文件下载时再次检查身份、归属及当前访问权限。授权撤销后不可继续获取结果；已在运行任务的取消/清理策略在任务服务中明确实现。

对外 API 密钥限制到指定能力/模型及授权范围，密钥只在创建时完整展示，后端按适当方式校验和保存；启停、到期、配额、失败和调用日志可追溯。

## 7. 技术实现与代码拆分

### 7.1 推荐路线

继续使用现有前端和 OpenLayers，不因新增分析功能重写门户。高级空间运算放到后端，前端负责输入、交互和结果展示。

| 层次 | 原型实施建议 | 正式接入建议 |
|---|---|---|
| 前端 | 原生 JavaScript 独立模块，复用地图组件和现有公共布局 | 继续沿用项目统一技术约束 |
| 几何运算 | 引入 Shapely/GEOS，处理相交、差集、融合、缓冲与有效性 | 可采用同一计算库，或对接既有 GIS 计算服务/PostGIS |
| 坐标处理 | pyproj/PROJ，显式声明源/目标 CRS | 使用业务确认的转换流程和精度要求 |
| 空间数据 | 少量明确标注的示例 GeoJSON，保存版本与覆盖范围 | 正式矢量数据库/文件服务及按授权获取的计算接口 |
| 任务执行 | SQLite 任务表＋独立 worker，幂等创建、领取、状态与结果落库 | 按任务量升级队列、对象存储和工作节点 |
| 报告 | 同一结果快照生成 HTML、GeoJSON、CSV | 服务端 PDF、文件存储与访问控制 |
| 外部模型 | 标准执行器接口，先接本地示例 | 逐提供方对接目录、认证、运行和结果格式 |

上述依赖是计划选型，不表示当前已经安装。若部署环境不能引入依赖，应选用已有 GIS 服务，而不是在现有简化几何函数上勉强拼出正式空间引擎。

WMS/WMTS 主要用于显示，不一定能提供要素几何；参与相交与面积计算需要可获得的矢量数据、WFS/要素 API、数据库或专门计算服务。

### 7.2 任务执行要求

任务状态建议为：排队中 → 运行中 → 成功/部分完成/失败/已取消。

- API 在短事务内校验并登记任务，返回任务 ID；空间运算和远程网络请求不占用当前全局数据库锁。
- worker 以事务领取任务，记录租约、心跳和执行次数，进程重启后可识别中断任务。
- 幂等键与用户、模型版本、输入摘要、参数摘要绑定；同键不同输入返回冲突。
- 取消、超时、受控重试和结果写入使用明确状态转换，防止重复生成报告或覆盖终态。
- 外部调用发生超时但执行结果未知时，先查询提供方任务状态，不能无条件重提造成重复执行或计费。
- 正在运行的任务固定工具、规则与数据版本；后续发布不会改变该任务含义。

### 7.3 文件与数据处理

上传接口与计算接口分离，文件保存在非公开目录，通过受权接口访问。校验文件类型、实际内容、大小、要素数量和顶点数；压缩包限制解压后大小、文件数量和路径，拒绝越界路径。

输入校验成功后再创建可执行任务；失败项逐项显示，不把空数据集当作“无冲突”。保留原件和标准化输入，输出与任务归属关联，避免用户根据猜测文件地址读取他人输入和报告。

初始限制建议：GeoJSON 单文件 10 MB、100 个地块、总顶点 50000；这只是原型保护上限的建议，实施时需配置并通过性能测试后确认，不作为正式性能承诺。

### 7.4 建议代码拆分

| 位置 | 调整内容 |
|---|---|
| 现有 `frontend/public-portal.js` | 保留能力入口，逐步将复杂分析与模型界面委托给独立模块 |
| 新增 `frontend/capability-market.js` | 模型列表、详情、筛选、申请和教程 |
| 新增 `frontend/analysis-workbench.js` | 地块输入、规则选择、任务状态、结果表与地图联动 |

## 8. 数据结构与接口

### 8.1 建议数据实体

| 实体 | 核心内容 |
|---|---|
| Capability / CapabilityVersion | 稳定 ID、工具/模型类型、来源、提供方、执行方式、输入输出定义、状态与不可变版本 |
| DatasetVersion | 数据集、来源、文件/API 标识、CRS、范围、有效时间、授权范围、摘要和版本 |
| RuleSetVersion / Rule | 规则版本、适用条件、依赖图层版本、谓词、阈值、依据和结论语义 |
| AnalysisInput | 归属、原始文件、标准化几何、字段、校验记录、摘要和版本 |
| AnalysisJob | 用户/组织、能力版本、输入版本、数据/规则版本、参数、幂等键、状态、心跳和时间 |
| AnalysisResult | 地块/规则明细、冲突几何、去重面积、比例、完整性、结论和文件引用 |
| AnalysisReport | 任务结果快照、模板版本、报告文件、摘要和生成时间 |
| CapabilityApplication / Grant | 申请人、能力范围、用途、审批、期限、授权状态 |
| ApiCredential / InvocationLog | 凭证标识、作用域、有效期、状态、配额、调用追踪与统计 |
| CapabilityGuide | 工具版本、说明、输入样例、预期结果和视频资源 |

页面与报告应引用同一 AnalysisResult。规则/模型/数据更新后重新执行生成新 Job，不原地修改旧任务快照。

### 8.2 接口建议

下列为后续接口契约方向，尚未实现。现有工程可先通过 `/api/action` 挂接同名领域操作，再为开发者提供稳定 REST 入口，二者共用鉴权和执行逻辑。

| 接口 | 用途 |
|---|---|
| `GET /api/v1/capabilities` | 按来源、类型、业务和状态分页查询 |
| `GET /api/v1/capabilities/{id}/versions/{version}` | 模型版本详情、输入输出与教程引用 |
| `POST /api/v1/analysis-inputs` | 上传/提交输入并校验，返回 inputId 和校验报告 |
| `POST /api/v1/analysis-jobs` | 创建分析任务，返回 202、jobId 和状态地址 |
| `GET /api/v1/analysis-jobs/{id}` | 查询所属任务状态、进度与错误 |
| `POST /api/v1/analysis-jobs/{id}/cancel` | 申请取消任务 |
| `GET /api/v1/analysis-jobs/{id}/result` | 获取授权结果与明细，支持分页 |
| `GET /api/v1/analysis-jobs/{id}/report` | 下载对应快照的报告 |
| `POST /api/v1/capability-applications` | 提交使用/调用授权申请 |
| `POST /api/v1/api-credentials` | 在审核授权范围内签发调用凭证 |

创建任务建议包含 `capabilityId`、`version`、`inputId`、`ruleSetVersionId`、`parameters`；幂等键通过请求头或明确字段传递。数据版本由服务端根据所选规则和权限解析并固化，不能信任客户端传入任意数据路径或外部 URL。

错误类型至少区分：输入/CRS 无效、数据缺失、未授权、版本冲突、超过配额、服务不可用、任务失败。响应给出可操作说明和追踪 ID，不向普通使用者暴露服务端凭证或堆栈。

## 9. 分阶段实施计划

### 阶段 A：真实计算的本地高级分析闭环

目标：可用示例地块与示例管控数据，真正运行空间核查并形成可追溯结果。

1. 增加输入、数据、规则和任务实体及增量迁移。
2. 完成 GeoJSON/绘制/粘贴输入，校验 CRS 与几何。
3. 引入空间运算引擎，补叠加、去重面积和规则评估。
4. 提供示例红线、基本农田、规划分区与明确标注的规则。
5. 完成任务执行、冲突地图、逐项明细和可打印报告。
6. 保留现有基础工具，补多地块和必要几何能力。

交付判定：无冲突、冲突、边界接触、部分覆盖、数据缺失、无权限和无效几何等案例有预期结果；变化输入会改变计算结果，不能返回固定“通过”。

### 阶段 B：模型市场与运营闭环

目标：前台体验来自后台已发布的模型版本，模型可维护、可授权、可追溯。

1. 统一工具/模型目录，完成来源层级与运行状态筛选。
2. 建设版本化输入输出定义和自动参数表单。
3. 打通规则、数据绑定、试运行、发布/下架与教程样例。
4. 增加能力使用申请、审批、个人授权及运行历史。
5. 完成候选地块比较和必要的人工确认交互。

交付判定：后台发布模型后前台可体验；草稿不生效；权限不足不能运行；国家级/自治区级来源有依据，缺少实际接入的模型显示真实状态。

### 阶段 C：正式服务与开发者调用

目标：接入经确认的管控数据、外部模型与工具 API。

1. 对接国家级/自治区级目录和模型服务，完成身份及执行适配。
2. 接入正式矢量数据、CRS 转换要求和经确认的业务规则。
3. 完成密钥申请签发、范围限制、撤销、配额和调用统计。
4. 提供稳定任务 API、开发文档、正式文件导出与 PDF 报告。
5. 按业务确认范围扩展规划数据文件格式和教程视频。

交付判定：真实服务返回结果可追溯；前台体验与 API 使用相同规则；故障与授权撤销得到正确处理。

### 阶段 D：规模与扩展

根据业务规模完善大文件、复杂几何、多 worker、批量任务、模型对比、收藏、运行告警和人工复核流程。全域自动选址、更多管控专题等扩展另行确认。

建议先实施 A，再完成 B；C 的资料与接口调研可与 A/B 并行。没有真实服务时可以完成可验证的本地闭环，但不能标为正式合规审查或正式国家级模型接入完成。

| AC-01 | 合法地块与完整规则数据，无交叠 | 所有必要检查完成，显示未发现所选规则冲突 |
| AC-02 | 与示例红线部分交叠 | 冲突几何、面积、比例与独立计算结果一致 |
| AC-03 | 仅边界接触 | 明确标记相接，面积为零；按相应规则处理，不混同面积占用 |
| AC-04 | 同类管控面重叠、跨类别交叠 | 同类面积去重，综合涉及面积不重复计数 |
| AC-05 | 含孔洞/MultiPolygon/多个地块 | 按支持范围正确处理，明细与汇总一致；不支持时明确拒绝 |
| AC-06 | 自相交、空几何、零面积、错误 CRS | 拦截并说明原因，不创建成功分析结果 |
| AC-07 | 管控图层缺失、过期或覆盖不完整 | 显示无法判定/检查不完整，不能输出整体通过 |
| AC-08 | 数据或能力未授权、访问他人任务 | 前端与 API 均拒绝越权访问或运行 |
| AC-09 | 修改同一工具的输入范围或参数 | 实际几何、面积与规则结果按输入变化，不使用固定结果 |
| AC-10 | 后台保存草稿、发布、下架模型 | 草稿不影响线上；新发布按新版本运行；下架阻止新任务 |
| AC-11 | 规则/图层更新后查看旧任务 | 旧任务继续显示原版本、原参数及原结果快照 |
| AC-12 | 相同幂等请求、重启、取消、超时 | 无重复任务执行/结果覆盖；状态和恢复符合约定 |
| AC-13 | 外部模型异常或返回格式不符 | 展示真实失败与追踪信息，不伪装成功 |
| AC-14 | 密钥停用、过期、超额 | 调用按约定拒绝，日志可查且不泄露完整密钥 |
| AC-15 | 地图、结果表和报告 | 使用同一任务快照，面积、单位、版本、未完成项一致 |
| AC-16 | 新用户按教程体验 | 样例可下载、参数可填写、结果能理解；视频可正常播放 |

测试需包含独立可算的标准矩形、相交矩形、重叠管控面和孔洞数据，并使用独立参考结果核对。面积比较容差应由方法和精度要求确定，不通过放宽断言掩盖算法错误。

浏览器验证覆盖上传、参数填写、任务状态、图表联动、历史与报告；接口验证覆盖授权、归属、撤销和版本；正式数据接入后增加业务方提供的已知案例验收。

## 11. 依赖与待明确事项

| 事项 | 需要确认的内容 | 不影响先行工作的部分 |
|---|---|---|
| 正式管控数据 | 来源、覆盖、时效、矢量格式、许可、更新机制、访问条件 | 用明确标注的人工示例数据完成 A |
| 政策规则 | 项目类型、适用条件、例外、阈值、单位、依据和结论措辞 | 实现通用空间关系与结构化示例规则 |
| 国家级/自治区级模型 | 目录地址、提供方、接入协议、鉴权、运行和结果示例 | 完成市场结构、本地执行器与接口契约 |
| 项目选址范围 | 已有候选地块比较，还是全域自动寻址与排序 | 首阶段按候选地块核查设计 |
| 文件与 CRS | GeoJSON、CSV、SHP、GPKG、CAD 等具体范围，坐标系和转换精度 | 首阶段限定 GeoJSON/绘制/坐标输入 |
| 身份与共享边界 | 个人、企业、机构的认证和可用能力、数据/派生结果权限 | 保留当前演示身份完成权限验证 |
| 报告与性能 | 正式模板、签章需求、并发、数据量、响应时限及保存期限 | 提供可追溯 HTML 报告与可配置限制 |
| 工期与分工 | 开发人员、接口可用时间、原型或正式交付目标 | 按阶段及验收结果组织，不虚设人天 |

本文建议下一轮编码先完成阶段 A 的“上传/绘制 → 校验 → 示例红线/基本农田/规划核查 → 任务结果 → 报告”闭环，再接阶段 B 的模型市场与后台统一管理。
