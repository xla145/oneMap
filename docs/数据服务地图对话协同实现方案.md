## 1. 建设结论与范围

可以将目前以卡片目录为主的数据服务，改造成地图与对话协同工作台。原要求规定分类、筛选、元数据、地图预览、申请和授权获取等能力，没有要求固定使用某种页面布局。

设计原则：

- 地图承担空间范围选择和数据预览；对话承担需求表达、条件补充与结果说明。
- 数据结果始终包含可操作的结构化卡片或表格，不仅返回文字答复。
- 保留主题目录、关键词和筛选功能，用户不需要提问也能找到资源。
- 在数据服务内完成对话及地图联动，不自动跳到独立智能助手。
- 保留现有资源详情路由、申请清单、审核与授权记录；新版详情抽屉调用相同领域接口。
- 选址、合规审查、缓冲、叠加等高级运算仍归能力服务。数据服务只负责发现、预览和获取数据。

本方案取代旧优化方案中“数据服务仅提供目录，智能提问跳到独立助手”的交互安排，仅对数据服务生效。办事服务仍按已确认方式：用户提问后进入独立智能助手。

## 4. 页面布局与交互

### 4.1 桌面布局

```text
首页 / 数据服务
数据服务                     数据目录  申请清单（n）  我的申请
关键词 [         ]  主题 [全部]  地区 [全部]  年份 [全部]  查询
已选条件：呼和浩特 ×   耕地 ×   最新可用版本 ×     清空条件
┌───────────────────────────────┬────────────────────┐
│                               │ 描述你需要的数据    │
│       左侧地图，约 65%         │ 用户需求 / 条件追问 │
│                               │                    │
│ 图层列表 · 框选 · 清除选区     │ 匹配到的数据        │
│                               │ 名称 / 年份 / 来源 │
│ 资源覆盖范围与预览图层         │ 查看详情 · 加载地图 │
│                               │ 加入申请 / 下载    │
│ 比例尺 · 图例 · 数据状态       │                    │
│                               │ [输入需求…] [发送] │
└───────────────────────────────┴────────────────────┘
```

- 不增加高大的欢迎横幅；标题、筛选、结果条件都采用紧凑布局。
- 右侧建议宽度 380～460px，地图使用剩余空间；比例随视口调整，不硬性压缩输入和结果卡片。
- 地图与对话容器等高；对话内容内部滚动，输入框保持可见。
- 数据目录通过抽屉打开，提供主题分类、分页列表、排序和推荐；选择数据后回到当前工作台操作，不清空对话。
- 条件过多时折叠次要筛选，避免工具栏不断增高。
- 详情使用抽屉，显示元数据、授权状态、字段/表格预览和获取方式。支持关闭后继续当前查询。

### 4.2 平板与手机

- 宽度不足以保持地图及对话可用时，提供“数据结果 / 地图”视图切换；二者共享同一查询和选区。这是小屏适配，不是另建助手页面。
- 手机上优先显示结果和输入框；查看空间分布时进入地图视图，返回后保留滚动位置与输入。
- 筛选和详情使用全屏抽屉；申请清单入口始终可达。
- 标题、按钮和表格均不得造成页面横向溢出；表格可在自己的容器内横向滚动。

### 4.3 初始、查询和无结果状态

初始：地图展示基础底图；右侧显示简短说明、示例问题及推荐数据入口。不得默认加载所有业务图层。

查询中：保留上一轮结果及范围，标记正在更新；新的结果返回后整体替换对应查询结果，避免混用两轮数据。

无结果：显示已使用的条件、无匹配的原因或限制，并提供“扩大地区”“取消年份”等可点击建议。不得静默放宽条件。

数据集没有可用几何：仍在结果列表显示，并解释“暂无地图预览”；不能用其他资源的图斑代替。

### 4.4 典型用户流程

用户输入“找一下呼和浩特最新的耕地数据” → 系统解析并展示条件 → 返回匹配目录 → 点击资源定位覆盖范围 → 有预览权限时加载图层 → 查看元数据 → 加入申请清单 → 填用途、期限和范围 → 用户确认提交。

用户继续输入“只看这块范围” → 若有明确选区则使用该选区，否则提示先框选 → 重新查询，显示范围参与的是目录覆盖筛选还是实际要素查询 → 用户可获取授权后的范围数据。

用户直接使用筛选工具栏 → 执行普通目录查询并更新地图/结果，不自动生成一条虚假的用户对话。

## 6. 需求理解与地图联动

### 6.1 统一查询状态

地图、筛选栏、对话不能分别维护三套互不一致的条件。统一 QueryState 至少包含：

- 关键词、主题代码、资源类型、行政区代码、年份/日期条件。
- 时间解释方式：数据所属年份、更新时间，或同一资源系列的最新可用版本。
- 范围模式：全部、行政区、自定义几何；几何引用、CRS、空间关系。
- 查询层级：目录覆盖查询或已授权要素查询。
- 分页、排序、用户确认的条件、状态修订号 revision。

条件来源记录为筛选栏、对话或地图。最近一次明确编辑覆盖同一字段，其他字段继承；修改筛选后旧结果标记待更新。清空范围只删除空间条件，不删除主题和时间条件。

### 6.2 自然语言处理路径

```mermaid
flowchart LR
  A[用户输入或筛选] --> B[解析与条件校验]
  B --> C{条件是否明确}
  C -->|否| D[澄清并保留当前结果]
  C -->|是| E[查询计划与权限检查]
  E --> F[目录或授权要素查询]
  F --> G[结果卡片及来源说明]
  G --> H[覆盖范围或授权图层]
```

首阶段使用可测试的词典与规则支持明确地区、主题、年份和数据类型。覆盖不了的表达提示补充条件或使用筛选，不返回伪造的智能理解结果。

设计可替换的需求解析适配器；后续接入真实大模型时，只允许输出经过 Schema 校验的查询条件及澄清问题。模型不能输出任意 SQL、任意资源路径、服务 URL 或直接生成授权结果。检索、空间计算、计数与权限由服务端执行。

### 6.3 “最新”和时间口径

“最新耕地数据”不能简单取整个结果列表中更新时间最大的一条。先定位相关资源系列，再选择该系列的最新可见版本，并显示该数据的实际年份和发布时间。

如果资源缺少数据年份/版本关系，只能显示“目录更新时间较新”，不能声称数据内容最新。历史年份不在库中时，提示无对应版本，不拿当前数据替代。对“最近”“今年”按服务端日期解析，并在条件摘要展示绝对时间。

### 6.4 地图行为约定

- 拖动、缩放地图只改变视野，不自动改变查询范围；用户点击“搜索当前范围”才应用范围。
- 框选后显示范围提示与“应用范围”操作。重复绘制明确替换旧选区。
- 卡片结果数为匹配的数据集数；图层命中数为该资源在授权范围内的要素数，不能混为同一指标。
- 目录覆盖范围命中只说明资源可能覆盖选区，不代表该范围内一定有要素。
- 未授权图层不加载真实要素；如果覆盖元数据也受限，则不绘制其范围。
- 首轮不自动叠加全部结果。可自动定位公开覆盖范围，业务图层由用户点击“加载地图”。
- 加载不同 CRS 的数据需明确转换；展示和计算使用的 CRS 分别记录，不能把演示经纬度变换当作正式测绘基准转换。

### 6.5 对话输出约定

回答格式以“本次条件 + 实际匹配结果 + 限制/缺失 + 下一步操作”为主。每个数据结论引用 resourceId、versionId 和可展示的来源。

用户要求统计时，仅对可访问且实际支持的字段和范围计算，并说明单位、数据时间、是否完整。缺字段或无法计算时不输出估算数字。涉及选址合规等高级分析时，显示能力服务入口，由用户选择跳转。

以上文件名为建议，编码时先检查现有职责，避免重复建立相同功能。

新会话建议单独建立 data_service_sessions、data_service_messages、data_service_queries 三类持久化记录。不要把全部地图要素和所有历史查询结果加入门户 bootstrap；按需查询、分页和获取几何。文件导出复用可用的任务模式，但以独立能力和权限定义注册，不将数据获取混入合规核查任务。

外部目录、模型或 GIS 请求以及复杂空间计算不得在现有门户全局状态锁内执行。读取必要授权/数据快照后释放锁，写回前检查会话修订与资源状态。

## 8. 数据模型与接口

### 8.1 关键实体

| 实体 | 建议字段 |
|---|---|
| DataResource / Version | ID、系列 ID、版本、主题、来源、数据时间、更新时间、类型、覆盖、CRS、格式、服务类型、限制 |
| DataSession | ID、归属、标题、QueryState、revision、创建/更新时间 |
| QueryRequest / Snapshot | 请求 ID、幂等键、会话、条件快照、请求修订、状态、可见结果引用、时间与说明 |
| DataMessage | ID、会话、角色、文本、结构化条件变更、结果快照引用、来源引用 |
| SpatialScope | ID、归属、原始/标准化几何、CRS、范围模式与空间关系 |
| ResourceAccess | 可发现、元数据可见、可预览、可申请、可下载、可调用 API、授权范围及期限 |
| ExportJob（阶段 C） | 用户、资源版本、授权依据、查询/裁剪范围、格式、状态、文件引用、到期时间 |

历史结果可保存资源版本引用，但每次恢复、预览和下载都重新检查当前权限及发布状态。历史会话不能成为已撤销权限的数据缓存出口。

### 8.2 接口契约建议

原型先接入现有 `/api/action`，采用 `data.*` 动作；稳定后可映射为 REST。现有动作不删除，兼容已有页面。

| 动作 | 主要输入 | 主要输出 |
|---|---|---|
| `data.catalog` | 筛选、排序、分页、可选范围 | 资源摘要、数据集总数、可用筛选项、版本及权限能力 |
| `data.session.create` | 会话标题、初始条件、幂等键 | sessionId、revision |
| `data.query` | sessionId、revision、requestId、文本或条件变更 | clarification 或 ready；标准化条件、queryId、分页结果与说明 |
| `data.query.page` | queryId、页码/游标 | 相同查询快照的下一页，不重新生成文字答案 |
| `data.scope.save` | 几何、CRS、范围模式 | scopeId、标准化范围摘要、校验错误 |
| `data.detail` | resourceId、versionId | 完整元数据、权限、获取方式和预览能力 |
| `data.preview` | resourceId、versionId、queryId、范围和分页 | 授权图层配置/要素页或表格页、总数及完整性标记 |
| `data.session.get` | sessionId | 授权过滤后的消息、条件、结果引用与视野 |
| `data.session.list` | 分页 | 当前用户会话摘要 |
| `data.export.create`（C） | 资源版本、queryId、范围、格式、幂等键 | 任务 ID、状态、预计输出范围 |
| `data.export.get`（C） | 任务 ID | 状态或短时有效的授权获取方式 |

申请提交沿用既有申请接口，补充范围、版本及用途字段；仍需打开申请表并由用户确认提交。API 密钥申请与数据包申请不能混作同一授权。

建议请求结构示意：

```json
{
  "sessionId": "session-id",
  "revision": 3,
  "requestId": "unique-request-id",
  "text": "只看这块范围里的耕地数据",
  "scopeId": "owned-scope-id"
}
```

响应必须给出本次 revision 和 queryId。前端仅接受当前 revision 的响应；用户切换条件、会话或身份后，旧请求即使晚返回也不能覆盖当前地图。

错误至少区分输入无效、需澄清、资源不可访问、预览未配置、授权到期、版本变化、范围不支持、请求过期和服务超时。错误文案应给出下一步操作。

## 9. 权限、性能与异常处理

### 9.1 权限与申请

身份始终由服务端读取，不能相信请求体中的 userId。所有资源、会话、查询、范围和导出任务均校验归属及访问范围。

可发现不等于可预览，可预览不等于可下载。不能通过统计总数、筛选项、来源引用、地图边界或缓存泄露不可见资源。字段隐藏规则同时应用于地图属性、表格、回答和下载。

申请区域或自定义范围必须保存为不可变快照；审批后下载范围不得超过授权范围。权限过期或资源下架时，旧结果仍可展示可访问的历史说明，但应禁用获取操作并移除受限数据。

### 9.2 性能与并发

- 目录和表格服务端分页；地图按选中资源、范围或瓦片加载，禁止一次返回全库要素。
- 首阶段可采用每页 10 条目录结果、最多同时加载 5 个业务图层作为可配置初值；上线前按真实数据量验证，不作为最终容量承诺。
- 底图失败显示本地备用底图或清晰提示，不让目录检索和对话一起失效。
- 请求可取消；写入幂等键绑定用户、会话、条件摘要，防止重复消息、重复申请或重复导出。
- 长耗时裁剪采用异步任务，不阻塞聊天与地图操作。
- 日志记录查询条件摘要、资源版本、耗时和失败类型，避免记录凭证或不必要的敏感数据正文。

### 9.3 发布与回退

开发和验收使用独立数据库，实施前备份已有数据。增量迁移不覆盖用户申请、资源、已有助手会话或授权记录。

先以受控开关接入新版 `/front/data`；验证完成后默认启用。保留旧目录渲染作为短期回退入口，旧资源详情链接继续有效。回退只切换界面，不删除已创建的申请和会话。

## 10. 实施阶段

### 阶段 A：完成基础地图对话数据服务

1. 建立页面骨架、统一状态与服务端目录查询。
2. 完成规则解析、明确条件展示、结果卡片和目录/筛选入口。
3. 接入资源覆盖定位、授权地图/表格预览与元数据抽屉。
4. 接通既有申请清单、申请表、授权示例下载。
5. 完成请求取消、旧响应隔离、无结果与无权限提示。

交付判断：用户可以通过对话或筛选找到同样的数据，加载正确图层、查看元数据并提交申请；对话留在数据服务内部。使用本地真实查询结果，演示数据明确标识。

### 阶段 B：完成空间追问和恢复

1. 框选/绘制范围与目录覆盖查询联动。
2. 支持实际可访问要素的范围查询，区分图斑数与数据集数。
3. 多轮条件增删改、冲突澄清、查询版本与可追溯来源。
4. 会话恢复、详情关闭/返回后状态保持、权限撤销后的重新过滤。
5. 申请范围快照与授权边界衔接。

交付判断：追问、筛选和地图修改不会产生互相矛盾的状态；换账号、迟到响应、权限变化均不能串数据。

### 阶段 C：补齐正式获取及原始要求

1. 接入正式数据源、准确时空元数据与资源版本关系。
2. 按授权行政区/自定义范围裁剪、异步下载与重试。
3. 实际 OGC/REST 服务、API 密钥申请和调用授权。
4. 真实访问/下载统计、热门推荐与后台统计。
5. 如有可用模型服务，接入模型解析适配器并评估准确性。

交付判断：按原始 2.2.1～2.2.10 逐项验收；原型已演示不等于正式交付。

### 阶段 D：可选体验增强

收藏条件、资源对比、共享查询链接（再次鉴权）、高级同义词/语义检索与规模化性能优化。另行确认范围，不默认增加全域选址或复杂模型计算。

## 11. 验收标准

| 编号 | 场景 | 预期 |
|---|---|---|
| AC-01 | 不使用对话，按主题和行政区筛选 | 有分页结果，可查看详情、地图和申请入口 |
| AC-02 | 输入明确地区、主题、年份 | 显示解析条件，只返回实际匹配的可见数据 |
| AC-03 | 问“最新数据” | 明确资源系列及实际数据年份；元数据不足时说明限制 |
| AC-04 | 地区、时间或“这个范围”不明确 | 提示澄清，不静默猜测并给出确定结果 |
| AC-05 | 无匹配资源 | 显示零结果和调整条件建议，不伪造数据 |
| AC-06 | 加载两个不同资源 | 地图显示对应数据，可分别显隐、移除和定位 |
| AC-07 | 浏览非空间表格 | 表格字段、分页、来源与权限正常；不生成假图斑 |
| AC-08 | 框选后应用范围并追问 | 地图、条件和结果一致；清除范围保留其他筛选 |
| AC-09 | 拖动地图 | 仅改变视野，未应用范围前查询结果不变 |
| AC-10 | 目录覆盖命中但无实际要素 | 区分覆盖候选与真实命中，不将目录数作为图斑数 |
| AC-11 | 未授权、已过期或跨用户访问 | 不返回受限几何、字段、统计或下载内容；给出合法申请出口 |
| AC-12 | 打开详情、加入清单、返回 | 对话、查询、选区和已加载图层保持；申请不自动提交 |
| AC-13 | 快速连续发送/切换筛选 | 旧响应不覆盖新结果，重复请求不产生重复副作用 |
| AC-14 | 恢复历史且权限已撤销 | 重新鉴权，隐藏受限数据，禁用已失效获取入口 |
| AC-15 | 按范围申请和下载（C） | 下载数据属于审批范围，格式/版本/字段权限一致 |
| AC-16 | 真实服务调用与热门推荐（C） | 服务和凭证可核验，访问/下载统计与后台记录对应 |
| AC-17 | 底图或服务加载失败 | 列表与对话继续可用，可重试，无虚假的加载成功提示 |
| AC-18 | 桌面、平板、手机 | 无页面横向溢出，输入和结果可用，地图切换保持上下文 |

验证应包含后端条件与权限测试、响应顺序及恢复测试，以及浏览器完整操作验证。测试问题必须包含不同结果、零结果、缺失元数据和拒绝访问，不能只验证按钮可点击。

## 12. 依赖与实施约定

| 事项 | 当前方案默认值 | 正式落地所需信息 |
|---|---|---|
| 界面与路由 | 新版 `/front/data`，保留旧详情 URL | 无需更换框架或重建门户 |
| 对话解析 | 首阶段规则与词典，接口预留模型适配 | 后续模型地址、能力与使用约束 |
| 地图与数据 | 先使用已授权示例资源 | 正式矢量/服务来源、CRS、许可与覆盖 |
| 时间与版本 | 分开记录数据时间、发布更新时间和版本 | 资源系列、更新机制、实际年份字段 |
| 权限与账户 | 复用演示身份和现有授权基础 | 正式个人/单位身份认证与分享策略 |
| 下载与调用 | 首阶段授权示例下载；正式裁剪、API 在 C | 可交付格式、范围授权、服务协议和凭证规则 |
| 工期与资源 | 按 A、B、C 阶段验收推进 | 人员、正式接口可用时间与数据量确定后估算 |

建议下一轮编码先完成阶段 A，使页面具备“说需求 → 返回实际数据 → 地图预览 → 详情 → 申请获取”的可验证闭环，再建设范围追问和正式服务接入。
