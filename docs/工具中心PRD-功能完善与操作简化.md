# 工具中心 PRD：功能完善与操作简化

版本：V0.1（评审稿）

日期：2026-09-17

状态：产品方向已逐项确认；2026-09-17 已按用户指示修复门户工具入口命名。其余功能设计与验收标准待评审，尚未开展整体功能重构。

## 1. 项目概述与已确认决策

### 1.1 产品目标

工具中心面向自然资源部门内部，提供可复用空间工具的发现、使用、申请与管理。此次调整不是删减功能，而是在保留原始需求的基础上，让业务人员不必理解接口、JSON 和图层版本号，也能完成空间数据处理。

普通用户的主线是：**找到工具 → 准备数据 → 执行操作 → 看懂并使用结果**。管理员的主线是：**登记工具 → 配置与检查 → 提交审核 → 发布维护**。

### 1.2 已确认的五项决策

| 编号 | 已确认方向 | 不可突破的边界 |
| --- | --- | --- |
| D-01 | 业务人员优先，接口资料与 JSON 调试放入“开发者接入” | 保留技术接入能力，不强迫业务人员使用技术界面 |
| D-02 | 同时简化前台使用和后台管理 | 上架审核、使用授权保持独立，不以统一入口替代审核 |
| D-03 | 七类工具独立入口、统一操作方式，结果可衔接下一步 | 不设计必须经过检查、入库等全部环节的长流程 |
| D-04 | 单工具直接申请，申请车仅作为批量申请入口 | 继续复用资源中心的申请、审核、授权期限和撤销机制 |
| D-05 | 完善可实际操作的本地原型，先 PRD 后代码 | 不接入生产 GIS；写操作沿用管理员限制；不得返回模拟成功 |

### 1.3 目标用户与权限

| 用户 | 主要任务 | 本轮处理方式 |
| --- | --- | --- |
| 业务使用者 | 算面积、转换坐标、叠加、检查和查询图形 | 图形化表单与可读结果；仅使用当前身份可见且获授权的工具及数据 |
| 工具管理员 | 维护工具、配置使用范围、办理上架审核与发布 | 统一工具管理入口；保持当前角色模型，不新增虚构岗位权限 |
| 具有写权限的管理员 | 图形入库、修改和删除 | 同时校验工具权限与目标图层权限，执行前确认 |
| 技术使用者 | 阅读接口文档、测试请求、查看调用方式 | 从具体工具进入开发者接入；仍受相同权限约束 |

“我的工具”指当前身份可管理的工具列表，不承诺本轮新增按创建人划分的所有权权限。普通用户不能通过开发者接入、跳转地址或直接请求获得写权限。

### 1.4 范围与优先级

- **P0，本轮必须交付**：七类工具的业务操作闭环；目录与申请简化；统一后台入口；授权、审核、版本冲突与错误处理；必要回归测试。
- **P1，本轮后续交付**：结果携带到下一工具、后台表格式接口资料维护、开发者界面整理。P1 不是删除项，完成后才能宣称本 PRD 全部交付。
- **不在本轮范围**：生产空间数据库、外部接口代理执行平台、地方专用界址点格式、七参数与控制点校正、新审批系统、新角色体系、大批量自动化流水线。
- 既有点缓冲、合规核查及外部工具入口继续保留；“七类工具”不是删除其他已发布能力的理由。

### 2.2 现有能力与真实缺口

| 领域 | 已有实现 | 本轮必须处理的缺口 |
| --- | --- | --- |
| 目录浏览 | 搜索、共享目录/部门/地市/类型筛选、数量、最新/最热排序、卡片 | 多条件集中展示；业务入口与接口资料的层级不清晰 |
| 工具详情 | 元数据、参数表、示例、在线 JSON 测试、JSON 下载 | 普通用户与技术用户共用复杂界面，结果主要为原始 JSON |

| 工作图层读写 | 查询、单图形入库、按 ID/唯一名称修改删除、版本校验 | 用户需手填资源 ID、要素 ID、revision；缺少选层选对象与冲突恢复交互 |
| 申请与授权 | 单个申请、申请车、资源审核及授权拦截 | 需收敛主操作，减少重复申请和跨页找入口 |
| 工具管理 | 注册、资料维护、上架审核、发布、下架、版本、权限、试运行 | `center-tools` 与 `portal-tools` 分散承载同一工具维护任务，表单暴露过多技术字段 |

检查、查询、入库、编辑模板目前默认面向管理员且需要审核发布。新界面不能自动发布模板，或为展示完整菜单而擅自扩大角色可见范围。普通用户验收所需的检查、查询工具应由管理员按正常流程配置和发布。

### 2.3 门户入口问题：有工具目录，但没有同名导航

2026-09-17 从本地门户首页实际点击核对：

- 顶部导航为“首页、数据服务、能力服务、办事服务、资讯下载、大美内蒙古”，没有名为“工具中心”的入口。
- 首页快捷入口叫“常用工具”，推荐区叫“常用能力”；点击顶部“能力服务”可到达 `/#/front/capabilities`。
- 目录主标题仍是“能力服务”，“工具中心”仅作为小字标识。因此问题不是目录路由不存在，而是需求名称、导航名称、首页入口和页面标题不统一，用户无法直接按“工具中心”找到它。
- 本次浏览器会话可见 7 项：坐标转换、面积量算、点缓冲区分析、叠加分析、项目选址与合规性审查、耕地变化监测工具、地灾风险辅助评估工具。这个数量不等于原始需求中的七类空间工具全部可用，不能据此判断检查、入库、编辑、查询已经面向该用户发布。

此前将目标信息架构写作“前台：工具中心”，不表示现状已经存在同名门户导航。实施时先补齐入口一致性，再完善各类工具交互；不得另建一个与“能力服务”并列且重复的目录。

修复记录（2026-09-17）：已统一顶部导航、首页快捷入口、目录标题、面包屑和使用指南中的“工具中心”名称，首页推荐区改为“常用工具”。保留 `/#/front/capabilities` 与 `/#/front/tools` 兼容，更新前端模块缓存版本。新增 3 项入口回归用例，JavaScript 测试共 16 项通过；实测桌面入口、390px 手机菜单和旧地址可打开目录，390px 与 1440px 无页面整体横向溢出。本次不代表七类工具业务操作和完整 AC-01 功能验收已经完成。

## 3. 总体交互设计

最新调整（2026-09-17）：用户要求首页菜单名称不要变化，已恢复顶部导航“能力服务”、快捷入口“常用工具”和推荐区“常用能力”。上文统一首页名称的修复记录仅为历史过程，后续以本段和 TC-01 为准。目录内部仍使用“工具中心”标题。

### 3.1 页面组织

```text
前台：工具中心
  工具目录：搜索、类型、排序、更多筛选
  工具操作页：准备数据 / 必要选项 / 结果
    工具说明
    开发者接入：接口文档、在线调试、调用方式
  我的申请与授权：复用资源中心
  申请车：批量申请次入口

后台：工具管理
  我的工具：草稿、待审核、已发布、已下架等状态筛选
  待审核：上架审核待办
  工具记录：基本信息 / 使用配置 / 发布记录 / 技术配置与试运行
  权限设置：低频管理入口
```

统一操作方式不等于每次弹出三步向导。桌面可在同一页分区显示，用户无需为每个区块点击“下一步”；查询等简单工具不出现无意义的上传步骤。

### 3.2 减少复杂度的方法

| 当前负担 | 简化方式 | 仍保留的能力 |
| --- | --- | --- |
| 先看接口说明再找到执行入口 | “使用工具”直接到业务操作页 | 工具说明、参数和示例仍可查看 |
| 默认展示全部筛选 | 搜索、类型、排序常驻；其余放入更多筛选 | 共享目录、部门、地市及对应数量 |
| 用户填写 JSON、内部 ID、revision | 业务表单、选层、选择对象，系统组装请求 | 参数验证、唯一标识与乐观锁 |
| 一项结果展示整段 JSON | 结果摘要、地图、明细表、下载 | 开发者界面保留原始返回 |
| 维护一个工具跨两个后台入口 | 围绕同一工具记录维护 | 审核、版本、下架、权限、试运行 |
| 单个工具也先加入申请车 | 一次点击进入申请表 | 多工具批量申请 |

不得把源坐标系、目标图层、叠加顺序、破坏性操作、未检查项或近似计算声明藏入高级设置。这些内容影响结果或风险，不属于可省略的技术噪声。

## 4. 前台功能需求

### 4.1 TC-01 工具目录与状态操作（P0）

- 页面主名称统一为“工具中心”，按七类业务任务呈现已发布、当前身份可见的工具。各类仍允许多个实际工具，不将类别入口伪装为已经发布的实例。
- 按用户最新要求，首页原有名称保持不变：顶部与移动端导航为“能力服务”，快捷入口为“常用工具”，推荐区为“常用能力”。进入后目录主标题为“工具中心”；面包屑沿用所属导航“能力服务”。保留现有 `/#/front/capabilities` 路由兼容，不新增重复菜单。
- 搜索框支持工具名称、介绍、单位及接口类型；类型与最新/最热排序常驻。“最热”明确按历史申请次数统计，不称为调用次数。
- 共享目录、部门、地市放入“更多筛选”；显示已选条件及一键清除。条件可由地址恢复，返回目录不丢失筛选。
- 卡片保留原始要求的截图、接口类型、名称、数源单位、上架时间、申请次数。截图缺失使用明确标识的功能示意图。
- 每张卡片仅突出一个主要动作；查看说明和加入申请车为次要动作。

| 状态 | 主操作 | 处理要求 |
| --- | --- | --- |
| 可直接使用 / 已授权 | 使用工具 | 内部工具进入操作页；外部工具进入已登记入口 |
| 需要授权且可申请 | 申请使用 | 直接打开复用的申请表 |
| 申请中 | 查看进度 | 不重复新建申请 |
| 授权到期 / 已撤销 | 按现有资源规则显示重新申请或不可用 | 不沿用旧授权继续调用 |
| 已下架 / 无权查看 / 入口未配置 | 无可执行主按钮 | 旧地址明确提示，不泄露无权查看的工具详情 |

类别下没有已发布可用工具时展示真实空状态，不显示可执行的假工具。外部入口的 HTTPS 校验和授权校验继续保留。

### 4.2 TC-02 单个申请与批量申请（P0）

- 单个申请自动带入所选工具对应的资源，沿用现有申请必填项和期限约束，仅让用户补充必要业务信息。
- 提交前显示申请对象、用途及期限；成功后提供查看进度入口，不显示“已可使用”。
- 申请车处理多工具选择和批量提交；同一工具不重复加入，取消提交不丢失原有选择。
- 工具需要申请授权时必须有合法关联资源；未关联时应在后台阻止发布该配置，不向用户展示无法完成的申请按钮。
- 上架审核通过不代表某用户已获得使用授权。新申请、到期和撤销继续由资源中心处理。

### 4.3 TC-03 公共数据准备与结果框架（P0）

**数据准备**：按工具需要提供“上传文件”“地图绘制”“选择已有图形”；文本坐标输入为补充方式。查询与单点转换无需强制上传文件，写入类选择目标图层不可省略。

- 上传支持既有 WKT、TXT、CSV、JSON、GeoJSON；TXT/CSV 继续限每行 `x,y` 或 `点号,x,y`，无表头，提供可下载格式示例。不宣称支持任意 Excel、Shapefile 或地方界址点格式。
- 提示文件格式、大小、几何类型与数量限制；解析失败定位原因，保留原文件与其他已填信息。
- 源坐标系必须明确。地图绘制可自动标注其已知坐标系；上传或粘贴时缺少可靠声明必须确认，不能根据数值范围静默猜测。
- 地图预览不是执行成功。非拓扑有效的图形仍应允许进入“图形检查”；无法解析的内容明确报错，不自动修复并冒充检查通过。
- 本地已有图形仅从当前身份可访问的工作图层读取，不能用后台全量数据代替权限过滤。
- 请求上限、几何数量与图层容量沿用服务端校验；普通模式初期采用不高于既有接口可承受的输入限额，超限在发送前说明，不静默截断。当前在线测试文件限制为 180KB、请求校验为序列化 JSON 长度上限，需注意两者及中文编码并不等价。

**执行与结果**：执行中防止重复提交；错误在对应输入附近显示并说明如何恢复，不清空有效输入。

- 有空间结果时显示输入与输出的区分图例、定位按钮和地图；非空间结果不强行增加地图。
- 有明细时用可读表格显示；原始 JSON 放入开发者接入，不作为唯一结果。
- 按真实返回提供适合的下载格式：图形 GeoJSON、转换结果 WKT/坐标结果、检查和查询明细 CSV；完整 JSON 下载保留。不得给非空间结果生成空 GeoJSON 冒充导出成功。
- 输入、坐标系或关键参数改变后，旧结果标记为“输入已变化，请重新执行”，不得继续当作当前结果用于后续写入。
- 所有结果明确本地/示例/近似范围，不作为正式测绘或审批结论。

### 4.4 七类工具的业务操作（P0）

| 编号 / 工具 | 用户必须提供或确认 | 业务结果与后续操作 | 补齐重点 |
| --- | --- | --- | --- |
| TC-04 叠加分析 | 图形 A、图形 B 或融合图形集合；运算方式；输入坐标系 | 重叠/差集/融合图形、面积、明细及下载；无交集显示有效空结果 | 独立叠加操作页，不默认进入合规审查；相交/差集明确 A、B 顺序 |
| TC-05 坐标转换 | 单点或图形文件；源、目标坐标系；必要的投影带定义 | 转换前后坐标、目标坐标系、WKT/结果下载、近似基准提示 | 业务表单覆盖现有 4326、3857、4490 与支持的 CGCS2000 投影，不退化为两个方向 |
| TC-06 图形检查 | 被检查图形及坐标系；行政区检查边界、共边检查参考图形按需提供 | 通过/不通过/未检查/已检查明细、原因与可定位对象 | 检查依据可从授权图形选择或上传；同坐标系适配；不能将“未检查”写成通过 |
| TC-07 图形入库 | 单个图形；目标本地工作图层；名称、必要业务属性、坐标系 | 新增对象、写入范围、结果计数；查看入库对象 | 选层代替资源 ID；系统生成唯一标识并允许业务标识输入；确认后写入 |
| TC-08 面积计算 | 一个或受支持数量的面图形及坐标系 | 单图形及明确口径的汇总面积，平方米/公顷切换，结果下载 | 普通模式复用服务端计算口径，不另建不一致的浏览器近似算法 |
| TC-09 图形修改 | 目标工作图层、查询选中的对象；新图形/属性或删除动作 | 修改前后摘要；确认后返回对象与状态 | 选对象代替手填 ID；保留未修改属性；删除独立危险操作，不加入批量删除 |
| TC-10 图形查询 | 已授权工作图层；关键词、行政区或定位坐标按需填写 | 结果数量、列表、地图定位和下载；有权限时可转入修改 | 条件可组合；查询作用于本地工作图层，不声称检索了生产 GIS 全库 |

补充规则：

1. 叠加保留既有面缓冲能力，选择缓冲时才展示距离；点缓冲入口继续可用。业务名称可简化，但不能删除相交、差集、融合、缓冲能力。
2. 面积汇总明确“逐图形求和”或“融合去重后的面积”，不可混用。带孔洞、多面及重叠图形按后端真实结果展示。
3. 图形检查的 `valid` 仅代表相应有效性结果，不能代替逐项检查结论。共边是关系结果，不自动判定错误；缺少行政区边界时即便基本检查通过，也须显示“行政区范围未检查”。
4. 现有检查接口未提供完整的坐标系规范化流程。本轮需补适配，将待检查图形及依据统一到明确坐标系，同时保留自相交等缺陷供检查，不用只接受有效面的通用分析校验提前拦截。
5. 入库一次写一个图形；多图形输入要求明确选择，不静默取第一项，也不承诺新增批量入库。工作图层现有容量限制继续生效。
6. 图形修改首轮采用替换上传图形或地图重绘，配合常用属性字段/键值表维护；不要求实现完整专业 GIS 顶点编辑器。
7. 查询页面可对返回结果分批展示，但应标明真正结果总数；不能因前端只显示一页就导出错误的全量数量。

### 4.5 TC-11 图层版本、写入确认与冲突恢复（P0）

- 选择图层或对象时系统读取并保存对应版本，用户不填写 revision。
- 提交携带用户查看、编辑所依据的版本。不能在写入前悄悄获取最新版本并替换，以此绕过并发冲突保护。
- 冲突时不写入，提示“图层已被更新，请重新加载并核对”；保留用户草稿，用户核对最新状态后重新确认。不得自动重试覆盖。
- 入库确认展示目标图层、对象名称/标识、图形预览和本地范围；修改展示目标对象与变更摘要；删除必须二次确认具体对象。
- 网络超时或响应不明时提示“结果待核实”，通过查询确认实际状态后再决定重试，不直接宣布失败或再次创建对象。
- 工具或目标图层下架、授权撤销、对象删除、身份变化均以执行时服务端校验为准。

### 4.6 TC-12 结果衔接（P1）

支持有明确意义的衔接：查询结果 → 面积/检查；叠加或转换结果 → 面积/检查；检查结果 → 入库；查询结果 → 修改。每次只带入用户明确选中的图形及属性、坐标系与来源，不自动执行下一工具。

- 下一工具仍需已发布且用户获授权。写操作入口仅对有权限者出现；服务端不能依赖按钮隐藏作为唯一保护。
- 检查存在未完成项时，下一页明确保留提示；明显无效图形不能绕过入库校验。图形检查不是所有入库场景的强制前置审批。
- 保留同一次页面会话内的临时数据即可，不新增长期文件仓库或任务平台。退出登录/切换身份清理上下文；刷新后的丢失风险明确提示。
- 切换图形、变更输入或进入不同目标图层时清除过期结果和 revision，避免串用。

### 4.7 TC-13 开发者接入（P1）

从具体工具的次级入口进入，展示基本信息、请求参数、返回说明、输入/输出示例、JSON 在线测试、原始返回及下载。接口仍复用现有 `portal.toolRun` 等动作，不另建具有更宽权限的调用通道。

调用凭证仅在实际使用方式需要时展示入口，复用现有凭证管理能力；不得将本地登录会话接口描述为已经提供对外生产 API，也不为每次普通操作强制创建密钥。外部工具未配置真实测试入口时，只展示资料与已登记访问方式，不伪造在线测试成功。

## 5. 后台功能需求

### 5.1 TC-14 统一工具管理入口（P0）

- 使用 `/#/admin/center-tools` 作为统一主入口；旧 `/#/admin/portal-tools` 保留兼容跳转或同源视图，不留下失效链接。
- “我的工具”显示当前身份可管理的工具，列表优先展示名称、类型、发布状态、审核状态、版本和状态对应操作。
- “待审核”只承载上架审核，不混入资源使用授权。工具列表中的“查看使用申请”跳转资源中心并携带可用筛选条件。
- 工具详情在同一记录中维护基本资料、使用方式、发布记录与技术配置；禁止保存两个彼此不同步的工具副本。
- 接口试运行记录和类型/模块权限从相应工具记录或管理设置进入，不作为日常业务使用者必须理解的主导航。

### 5.2 TC-15 注册与维护表单（P0，接口资料表格化为 P1）

| 区域 | 默认展示 | 按条件展开 |
| --- | --- | --- |
| 基本信息 | 工具名称、用途说明、类型、发布/提供单位、目录、地区 | 截图、排序及补充介绍；已有单位信息可预填但需确认 |
| 使用配置 | 执行能力、允许角色、直接使用/申请授权 | 申请授权时选择关联资源；外部工具时填写有效入口 |
| 技术配置 | 内部组件显示可继承的默认参数与说明 | 参数定义、请求/返回示例、接口类型等高级维护 |
| 提交检查 | 缺失项列表与直达修正位置 | 无阻塞问题时允许提交审核 |

- 内部组件预填已有协议，不要求管理员重复编写 JSON；参数资料编辑提供名称、类型、必填、说明的表格，并兼容已有 JSON 数据。
- 截图仍校验 PNG/JPEG/WebP 和现有 2MB 上限；未上传可使用示意图，不虚构真实截图。
- “登记内部组件模板”成为新增工具时的可选模板来源，仍创建草稿；重复登记不重复创建，不能自动审核或上线。
- 写入类工具强制管理员使用，不能通过配置表单将其改为普通用户可写。
- 关联资源维护的单位、地市、共享编目继续按既有来源规则展示，避免用户在两处重复维护并产生冲突。

### 5.3 TC-16 审核、版本与下架（P0）

- 在界面上分别表达“发布状态”和“当前草稿审核状态”，避免把“线上旧版可用、新版待审核”错误显示为整项工具不可用。
- 注册/修改 → 保存草稿 → 提交审核 → 审核通过 → 发布；驳回显示原因并允许修改后重提。审核意见要求继续保留。
- 受审配置变化后审核失效并需重新提交；不得因为字段收进高级设置而从审核签名中排除截图、接口资料或权限相关配置。
- 编辑已发布工具时，在新版本完成正常审核发布前，前台继续使用已有发布快照。
- 下架需确认影响，停止后续调用；直接请求与旧地址均不能绕过。再次发布按现有有效审核与配置一致性规则执行。
- 版本记录保留版本、发布时间和相关审核信息；本轮不新增未经定义的一键回滚、自动发版或免审发布。

### 5.4 TC-17 权限与试运行（P0）

- 保持“单工具角色 + 关联资源授权 + 类型/功能模块附加限制”的组合逻辑；权限设置明确说明限制规则命中后禁止使用，不误导为授权白名单。
- 权限集中维护，不在两个后台页面重复配置。保存仍携带配置版本，发生冲突要求刷新核对。
- 前台操作、开发者测试、后台试运行分别说明执行范围；后台写入试运行确实可能修改本地数据，必须与普通写操作一致地展示确认，不标成无副作用预览。
- 试运行保留输入、耗时、结果或错误；测试通过不等于已审核或已发布。

## 7. 技术约束、实施顺序与评审交付

### 7.1 技术约束

- 延续当前原生 JavaScript 前端与 Python 后端，优先复用已存在的地图、文件解析、空间计算、资源申请和权限机制，不引入新的前端框架或审批引擎。
- 保留既有工具 ID、资源关联与发布快照，统一页面不迁移成平行数据源。旧路由保留兼容，更新链接后执行回归。
- 普通操作与在线接口尽量共用执行口径；如旧简易计算路径与后端不同，先确定统一口径、补一致性测试，再替换界面，避免“同样输入不同结果”。
- 工作图层与生产 GIS 严格区分；无外部接入时明确“本地工作图层”或“未接入”，不能用示例数据暗示真实生产结果。
- 附加输出不得泄露调用凭证；CSV 导出对可被表格程序解释为公式的业务文本作安全处理；文件与输入仍由服务端验证。
- 现有正在修改的运营中心文件和技能删除不属于本 PRD。后续若需修改共享 `app.js` 等文件，应保留这些在途改动，只调整工具相关部分。

### 7.2 实施里程碑

| 阶段 | 工作内容 | 完成标志 |
| --- | --- | --- |
| M0：本文评审 | 确认页面组织、七类工具操作、权限边界和验收清单 | 用户明确同意 PRD 后再改代码 |
| M1：普通使用闭环 | 公共输入与结果、七类操作表单、目录与申请简化、统一计算口径 | P0 前台验收及相关权限/空间测试通过 |
| M2：管理闭环 | 后台统一、注册与维护、审核版本和下架、冲突与写入确认 | P0 后台验收与原流程回归通过 |
