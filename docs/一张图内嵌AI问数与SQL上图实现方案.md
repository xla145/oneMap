# 一张图内嵌 AI 问数与 SQL 上图实现方案

日期：2026-09-16。状态：首期原型已实现。下文第 1～8 节保留目标方案，当前完成范围以第 9 节为准。

## 1. 目标与页面

在 `/#/admin/integration-results` 的现有地图中加入“AI 助手”，完成业务提问、条件补充、空间查询、结果上图与连续追问。

- 地图右侧提供可收起的对话面板，建议桌面宽度 380～420px；收起后保留助手按钮。
- 与现有业务详情、工具面板协调开关，避免同时占满地图。开启对话不重新初始化地图。
- 对话输入可附带当前行政区、参与查询的图层、选中对象或用户绘制范围。查询范围需可见、可清除；平移地图不自动改变查询条件。
- 地图底部按需打开结果表格，支持行与图形双向定位。手机采用地图、对话、结果切换，状态共享。
- 普通用户查看业务结论、统计口径和数据来源；生成 SQL、参数和执行耗时折叠在“查询依据”中，并按角色控制显示。

示例：“找出呼和浩特市 2025 年面积超过 20 亩的新增建设用地图斑。”结果显示命中数量、面积统计与图斑分布。追问“只看未审批的”，继承上一轮区域、年份和面积条件并新增审批状态；缺少关联审批数据时明确说明，不能把缺数当成未审批。

## 2. 当前可复用基础

| 文件 | 可复用能力 | 本次需要新增 |
| --- | --- | --- |
| `prototype/frontend/results-workspace.js` | 一张图工作区、业务主题、工具与应用面板 | AI 面板入口、展开收起及业务上下文 |
| `prototype/frontend/integration-map.js` | 地图实例、图层与选中对象、选区回调、对象定位 | 为助手提供上下文及独立结果图层接口 |
| `prototype/frontend/map.js` | OpenLayers、GeoJSON、范围定位、分析要素展示 | 按查询 ID 管理结果图层，避免覆盖工具计算结果 |
| `prototype/server.py`、`prototype/spatial.py` | 会话、身份、资源权限、部分空间上下文 | 地图问数专用接口与多轮查询状态 |
| `prototype/capabilities.py` | 预设 SQL 模板、授权示例表、SQLite 只读查询 | 业务语义目录、查询计划编译、SQL 校验、真实数据适配 |

现有助手并非通用大模型，当前 SQL 能力是在内存 SQLite 中查询授权示例表。已有地图协同代码和文档可以参考，但不能视为自然语言生成空间 SQL 已经实现。此次入口位于一张图，不需要恢复此前撤下的独立智能中心地图页面。

## 3. 推荐处理链路

1. **请求上下文**：提交问题、会话 ID、地图场景、选区和参与图层；后端重新核对当前身份与授权。
2. **业务元数据检索**：只向模型提供获准查询的数据集、字段、枚举、时间口径、单位和允许的关联关系。
3. **意图解析**：模型生成结构化查询计划，包括业务对象、筛选条件、统计指标、空间关系、排序和展示方式。缺少年份、对象或业务定义时先追问。
4. **SQL 编译与校验**：由后端把计划编译成参数化 SQL；复杂查询可使用模型候选 SQL，但必须经过语法树、表字段、函数及关联白名单校验。权限范围由后端强制实施。
5. **受控执行**：通过只读数据源执行，限制查询时间、复杂度和结果规模；统计与分页查询共享相同条件和数据版本。
6. **地图结果组装**：返回业务摘要、统计、表格行、空间要素或结果图层引用。摘要中的数值以实际执行结果为准。
7. **前端展示**：创建本轮临时图层，按需定位、高亮及打开表格；支持隐藏、移除、另存结果和继续追问。

首期建议采用“模型识别业务条件 + 后端受控 SQL 编译”。用户仍能追溯最终 SQL，同时避免依赖模型临时猜测真实表名、关联条件和业务口径。

## 4. 必备业务数据配置

每个可查询数据集至少登记：资源 ID、授权规则、数据源和表 / 视图、字段类型、中文业务名称、枚举与别名、唯一主键、空间字段及坐标系、行政区字段、时间字段、数据版本和更新日期。

业务字典还需定义“新增建设用地”“未审批”“高风险”“违法占地”等术语的实际判断条件，以及“亩 / 公顷 / 平方米”换算与面积来源。面积必须区分登记面积、整幅几何面积和选区内交叠面积；跨表统计需按业务主键处理重复记录，避免关联后重复累计。

地图上图支持两种映射：

- 数据含 `geom`：后端转换成展示坐标系，并返回完整 GeoJSON 点、线、面。
- 业务表无空间字段：通过已登记的 `feature_id`、地块编码或项目编码关联空间图层；缺少可靠关联时只返回表格，说明不能定位，不猜测坐标。

正式空间查询建议使用 PostgreSQL + PostGIS，支持相交、包含、周边距离和空间索引。已有其他空间数据库时优先通过适配器连接，不强制迁移。原型可用 SQLite 查询属性，再由 Shapely 完成空间过滤，但不能把该路径描述为已具备 PostGIS 服务。

## 5. 地图查询类型

| 提问 | 查询与展示 |
| --- | --- |
| 某市某年的某类图斑 | 行政区、时间与分类筛选，返回图斑图层 |
| 圈选范围内面积超过阈值的地块 | 空间关系与业务条件组合，明确面积口径 |
| 某项目周边 1 公里地灾隐患 | 距离查询，返回隐患点及查询范围；距离单位为米 |
| 按旗县统计耕地面积 | 分组统计，匹配行政区边界制作分级设色图 |
| 这些地块是否涉及生态红线 | 精确叠加计算与交叠范围，不把普通属性查询当作合规结论 |
| 只看未审批的 / 换成去年 | 在已确认查询计划上修改条件，保留每轮条件快照 |

## 6. 接口与结果契约

建议增加：

- `integration.ai.ask`：业务问题与地图上下文，返回追问或查询任务。
- `integration.ai.result`：查询状态、摘要、统计、分页行和地图结果。
- `integration.ai.cancel`：取消正在执行的查询。
- `integration.ai.history`：本人历史任务，恢复时重新核对权限。

结果建议包含 `queryId`、`sessionId`、`status`、`interpretedFilters`、`summary`、`total`、`rows`、`mapResult`、`statistics`、`sources`、`warnings`。地图结果包含要素 ID、GeoJSON 或服务端图层引用、坐标系、范围、图例、已加载数量与是否截断。

少量结果可用 GeoJSON；大量结果采用服务端分页、按视口加载或矢量瓦片，点数据可聚合。统计总数不能用当前页要素数量代替。聚合结果应关联行政区或网格几何，而不是强行还原为不存在的单个业务对象。

地图行为使用明确的服务端结果类型和前端白名单，不执行模型生成的 JavaScript、任意图层地址或未经校验的样式。

## 7. 实施顺序

1. **基础配置与首个业务闭环**：选择一个已有可靠几何的业务数据集，明确字段、权限、术语和面积口径；在地图中接入助手面板、查询结果图层与联动表格。
2. **真实语义解析**：配置模型服务适配器，将自然语言转换为受约束的查询计划；实现澄清、多轮追问、参数化 SQL 与执行审计。规则演示模式须明确标识，不能冒充模型调用。
3. **空间查询与统计**：接入正式空间数据源，补空间关系、距离、跨表关联及区域设色统计，优化查询与地图加载。
4. **业务扩展**：接入已有工具箱中的叠加、合规核查等能力，添加结果保存和历史恢复。

实施前需要落实的配置是模型服务、首批业务表及空间关联方式；连接凭据保留在后端配置，不放入浏览器。

## 8. 验收要点

- 自然语言、展示条件与最终 SQL 一致；查询结果能与人工 SQL 对照。
- 权限外的表、字段、区域和要素不可查询；只读查询不能通过函数或其他 SQL 结构间接修改数据。
- 同一查询的地图、表格、数量、统计口径和数据版本一致。
- 查询无结果、无权限、缺少空间关联及执行失败分别展示。
- 多轮继承条件正确；切换会话或快速连续提问时，旧请求不覆盖当前结果。
- 助手图层与工具箱分析结果独立管理，不互相清除；开启助手不重建地图或丢失视野。
- 历史结果恢复、导出和后续分页都重新校验授权。


## 9. 首期交付范围（2026-09-16）

已在一张图现有地图内接入 AI 助手侧栏，不重建地图。查询、SQL 与参数依据、全量数量及登记面积、分组统计、每页 100 条表格与 GeoJSON、最多 5 个独立紫色图层、定位高亮、显隐移除、历史查询及下载本页已接通。手机绘制范围时侧栏缩为底部提示条，完成绘制后恢复。

后端新增 `prototype/map_ai.py`；基于服务端当前授权地图的要素生成临时 SQLite 表，由受约束计划编译参数化 SQL。空间相交使用 SQL UDF 调用 Shapely，周边范围使用局部等距投影计算，执行前验证经纬度、拓扑和角色面积上限。统计、分页共享同一条件；历史读取、分页及导出重新校验权限和数据指纹。

接口均通过 `/api/action`：`integration.ai.ask/result/history/cancel`。目前是同步请求，无异步任务轮询、sessionId 或中途终止模型网络请求；前端「停止等待」防止迟到响应上图，返回后将记录标记取消。服务端按用户保存最近 50 条查询计划，最近查询入口最多展示 20 条；不持久化地图要素副本。历史恢复用于查看，后续提问按当前地图范围开始新一轮；当前会话的正常翻页保留追问条件。

当前本地规则解析明确标注「未接入大模型」。可用 `MAP_AI_PLANNER_URL` / `MAP_AI_PLANNER_TOKEN` 接入 JSON 规划网关；网关协议及示例见 `prototype/README.md`，不能直接填写通用聊天模型 API 地址。模型返回结构化计划，不执行模型生成 SQL。网关调用在全局状态锁之外执行，返回后重新检查权限并仅合并新增查询，避免覆盖其他请求变更。

与目标方案的差异：

- 使用授权地图的示例数据，未接入生产数据库或 PostGIS；建设用地样例是点，不是真实地块面。
- 表格位于助手侧栏，不在地图底部；SQL 依据对具备空间分析权限的助手用户可见，尚无独立 SQL 查看权限。
- 面积为登记面积之和，不做几何裁剪、去重、跨表关联或合规判断。
- 按地区统计提供数值及命中要素，尚未实现行政区分级设色。
- 本地解析仅支持明确列出的字段和表达；未知地区、业务口径、否定或未识别条件要求澄清。
- 未实现流式回复、服务端矢量瓦片、长期成果保存或模型供应商直连适配。

测试覆盖见 `prototype/test_map_ai.py` 和 `prototype/check_map_ai_browser.py`。启动及配置细节见 README 对应章节。
