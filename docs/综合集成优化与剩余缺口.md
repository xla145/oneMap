# 综合集成优化与剩余缺口

日期：2026-09-16。用途：后续后台功能设计、原型迭代和分项验收。

依据：[正文与附表合并分析](../img/运营中心/综合集成_正文与附表合并分析.md)、[40项实现追踪](综合集成深化实现说明.md)。优先级和下述后台组织建议属于设计建议，不是可研原文的新增强制要求。

## 1. 当前判断

综合集成已形成数字资源门户、后台成果地图、个人工作台和配置后台，但仍是使用示例数据的可运行原型。主要问题已从“缺入口”转为“业务闭环不完整”：外部系统只有配置与本地交换、地图缺正式三维和时序能力、租户隔离尚未覆盖所有业务模块、监测缺真实接入计划及执行链路。不能按附表40行页面覆盖率推算完成率。

## 2. 本轮已优化

| 优化 | 当前行为 | 边界 |
| --- | --- | --- |
| 发布与恢复 | 基础设置、展示内容、公告保存发布历史；支持已保存草稿预览、按身份检查范围、恢复历史版本到草稿 | 恢复后必须再次发布；单项预览不等于整页所见即所得编辑 |
| 素材上传 | 图片支持PNG/JPEG/WebP上传、压缩、预览和清除；长表单保存区固定可见 | 视频仍使用HTTPS地址；无素材库与对象存储管理 |
| Banner轮播 | 手动切换、3～30秒自动轮播、暂停；悬停、焦点与后台页暂停，适配减少动态效果偏好 | 不等于公告文字轮播或全站主题替换 |
| 定向公告与内容 | 角色、部门、租户、有效时间取交集；成员撤权后重新校验可见性 | 未选择部门/租户表示不限；不包含外部短信或邮件投递 |
| 搜索详情 | 知识和智能体定位到具体对象；搜索后立即更新本人热词 | 平台级热词、跨来源相关性、搜索和实际调用联合推荐仍缺 |
| 集成监测 | 日期、调用部门、结果筛选，日/周/月趋势；成功、失败、外部入口打开分别计数 | 目录存量不随事件筛选；浏览器事件不是外部执行凭证 |
| 查询面积限制 | 门户总阈值及更严格的角色阈值，发布后服务端执行 | 不包含个人例外、行政区数据范围或数据密级策略 |

地图展示后续增量：已补自动加载、图层检索/资源分类与来源分组、图例、行政区定位、结果定位和范围展示；最新实现及地图剩余项见 [地图展示优化说明](综合集成地图展示优化说明.md)。GI-06中的正式四维目录、时序和专题数据仍待完成。

## 4. 后台设计还应调整什么

1. **成果编排补归口与来源关系。** 当前主题、部门和行政区字段不足以解释“场景来自哪个业务系统、依赖哪些图层和工具”。建议关联既有系统、资源、工具主记录；不另造同名主对象。
2. **接入对象与执行记录分开。** 内部/国家/纵向/横向页保留各自业务字段，共用交换任务、运行记录和失败详情；配置完整只说明可以准备联调，不能显示成已联通。
3. **监测首页能下钻。** 数量卡片进入相同筛选条件的记录列表，失败排行进入错误详情，接入计划有责任部门和进度。当前统计和依赖检查尚未形成这套闭环。
4. **权限设计贯穿所有入口。** 菜单可见、目录可见、详情可读、数据可用和任务可办应分别校验；工作空间权限不得自动转化为平台资源授权。
5. **工作台配置交由岗位与个人共同控制。** 管理员配置默认模板与强制项，用户调整收藏、分组和提醒；业务指标来源需要明确字段和授权，不能只增加空卡片。
6. **状态文案反映实际过程。** 发布、同步、接入和执行分别建模；本地校验通过、配置完整、已联调、运行成功不能混用。

## 5. 下一阶段建议顺序与依赖

可先在现有原型内设计和实现GI-07接入计划与异常下钻、GI-09公告事件联动、GI-10岗位模板。这些工作能进一步补齐后台流程；接入计划中的外部运行结果仍需真实接口才能填充。

并行准备外部系统接口规范、测试环境、认证协议、用户和任务映射、国家节点规则，以及正式图层/地形/模型、坐标与高程基准、八专题计算口径。GI-01至GI-06依赖这些条件，不能仅凭新增页面验收。

继续实施时按“需求编号 → 页面/对象 → 操作和权限 → 数据来源 → 运行记录 → 验收样例”维护追踪，不以测试通过数量替代业务覆盖。
