## 1. 背景与设计目标

### 1.1 现有需求的重设计问题

原《一张图成果.md》包含空间图层、工具箱、场景集成及监测能力，已经说明“提供什么”，但没有展开用户围绕区域或地块如何完成具体工作。若直接按章节做成图层列表、工具列表、应用列表和监测图表，业务人员仍需自行拼接数据、工具和应用。

重设计以空间对象串联业务：用户先在图上确定区域、地块或项目，系统根据所选业务组织相关图层、指标、分析工具、结果及应用入口。地图上的同一个对象应能连续完成查看、分析、追溯和成果输出。

### 1.2 核心目标

| 目标 | 期望行为 | 验收方向 |
| --- | --- | --- |
| 地图成为业务入口 | 进入页面即看到授权区域地图，可直接点区域或查地块 | 首屏能完成定位、业务切换和图层操作 |
| 业务带出数据和工具 | 选择“地块综合核查”后自动展示核查图层、输入和执行动作 | 无需先去工具中心寻找分析服务 |
| 一处选择，全局联动 | 区域、年份、对象在地图、指标、台账和报告间一致 | 所有结果显示相同范围与版本 |
| 分析有可追溯证据 | 结果能定位命中范围、查看数据来源及规则 | 每条命中结果至少关联对象、图层版本、计算项 |
| 成果可复用 | 保存地图方案、历史分析和输出文件 | 恢复后可辨认原始快照与当前数据差异 |

### 1.3 推荐主线

**以区域看全局、以地块查关系、以项目追成果、以时间看变化。**

首版优先贯通四条流程：区域资源研判、地块综合核查、时序变化对比、业务成果追溯。工具和场景围绕这些流程提供能力；运行监测放在独立入口。

## 3. 用户与产品边界

### 3.1 用户

| 用户 | 主要问题 | 首选路径 |
| --- | --- | --- |
| 管理层 | 某区域资源现状如何、哪里变化明显、项目进展如何 | 区域定位→资源概览→专题钻取→汇报成果 |
| 业务人员 | 这块地涉及哪些管控范围、关联哪些审批或供应成果 | 地块定位/绘制→综合核查→证据查看→关联业务 |
| 分析人员 | 多地块、多年份、不同区域有什么差异 | 批量输入/时间选择→分析→图表台账→导出 |
| 成果与运行管理人员 | 数据是否齐全、哪些资源和工具被使用 | 成果监测→资源/工具/场景详情→来源中心 |

管理层默认浏览与研判，不默认获得编辑、批量分析或下载权限。具体权限由授权决定。

### 3.2 本产品负责

- 地图浏览、目录发现、区域与地块定位、要素查询。
- 基于已发布数据和工具开展空间查询、业务核查与趋势分析。
- 展示业务对象及其关联成果、阶段和来源系统入口。
- 地图方案、查询历史、分析任务、成果输出与汇报展示。
- 资源、工具和场景的集成使用监测。

数据采集治理、工具开发与发布、应用搭建分别由对应中心承担。正式审批、执法立案、整改销号、项目验收等动作在权威业务系统办理；本产品承接地图查询、辅助研判、成果展示及上下文跳转。若未来需要办理回写，应另行明确业务责任和接口。

## 4. 信息架构与地图布局

### 4.1 入口结构

```text
一张图成果（统一地图工作台）
├─ 综合看图：区域概览、资源专题、对象查询
├─ 业务专题：八类应用主题、主题内地图业务
├─ 地块核查：选择范围、八项专项查询、批量任务
├─ 时序对比：影像/现状/规划、变化结果
├─ 工具箱：常用空间工具、三维分析、工具目录
├─ 成果监测：图层、工具、场景运行情况
└─ 我的成果：地图方案、查询历史、分析成果、汇报方案
```

八类应用主题沿用原文：自然资源“大管家”、国土空间规划、耕地保护和国土绿化空间、要素保障、矿产资源、生态修复、督察执法、灾害防治。调查监测作为共用数据业务专题进入“大管家”等相关主题，不额外替换原文分类。

### 4.2 页面分区

```text
┌──────────────── 标识 / 主入口 / 统一搜索 / 用户 ────────────────┐
│ 区域面包屑 / 业务专题 / 年份版本 / 当前分析范围 / 数据状态       │
├────────────┬─────────────────────────┬───────────────────────┤
│ 左侧面板   │ 地图主工作区            │ 右侧上下文面板        │
│ 业务任务   │ 区域、图斑、项目        │ 区域摘要 / 对象详情   │
│ 图层目录   │ 查询、绘制、分析结果    │ 分析输入 / 核查摘要   │
│ 已加载图层 │ 工具条、图例、比例尺    │ 关联成果 / 统计       │
├────────────┴─────────────────────────┴───────────────────────┤
│ 底部可折叠结果区：结果台账 / 任务进度 / 时序对比 / 历史         │
└─────────────────────────────────────────────────────────────┘
```

- 主参考尺寸1920×1080，兼容1366×768。左侧建议280—320px，右侧320—380px；窄屏自动收起一侧，避免双侧同时挤压地图。
- 常规工作态地图未被面板遮挡的可操作区域不少于工作区面积50%；全屏结果查看属于用户主动进入的临时状态，关闭后恢复地图。
- 首屏使用简洁行政区底图，加载自治区/当前授权区域边界，避免一次加载所有专题要素。右侧展示3—5个有来源的关键指标。
- 继承 demo 的深绿业务主色、浅色面板和清晰图例；风险用色同时配合文本/符号，不能只依赖红绿区分。
- 左侧在“业务任务、图层目录、已加载”之间切换；右侧一次展示一个主要上下文，地图点选切换为对象详情。
- 原始字段、接口等技术详情仅在来源详情或管理视图中显示，常规业务界面使用业务名称。

### 4.3 地图上下文规则

| 上下文变化 | 地图行为 | 结果行为 |
| --- | --- | --- |
| 选择自治区→盟市→旗县 | 定位选区、突出边界 | 区域摘要与台账重算，显示区域面包屑 |
| 单纯拖动或缩放 | 仅改变视野 | 不暗改业务统计范围；可主动选“按当前视野统计” |
| 切换业务专题 | 保留区域和可兼容年份，加载专题默认图层 | 更新业务动作与指标，旧任务仍在任务中心可查 |
| 更换年份或数据版本 | 切换对应图层；无该年份则提示缺失 | 已有分析标记“输入已变化，需重新分析” |
| 点击对象或结果行 | 定位并高亮同一对象 | 详情面板与选中行同步，保留原筛选条件 |
| 关闭结果面板 | 保留当前图层与选中对象 | 收起结果，不删除已完成任务 |

## 5. 核心业务流程

### 5.1 区域资源研判：某盟市的资源格局与变化

**示例问题：**查看鄂尔多斯某年度土地利用结构，找到建设用地集中区域并形成汇报图。

1. 选择盟市及年份，地图定位，右侧更新该区域资源摘要。
2. 点击“土地利用结构”，加载现状分类图层，显示分类型面积、占比与来源。
3. 点击“建设用地”图表项，地图突出对应要素，底部列出关联地块。
4. 点击旗县或台账记录继续下钻；面包屑支持返回上一级。
5. 开启另一年度对比，查看变化范围和变化量；无可比数据时明确说明。
6. 保存当前地图方案或生成区域资源成果，保留范围、年份、图层版本及统计口径。

**完成标志：**从区域概览可以追到具体空间对象，导出成果与当前选择一致。

### 5.2 地块综合核查：拟用地范围涉及哪些限制和关联成果

**示例问题：**核查某拟建项目地块是否涉及永久基本农田、生态保护红线等范围，并查看审批与供地记录。

1. 选择“地块核查”，通过图上选取、绘制或已登记项目范围建立待查地块。
2. 为每块地设置名称，确认坐标、面积和所处区划；导入方式按版本规划开放。
3. 选择八项专项查询，系统展示各项数据年份、版本、可用性和必需输入。
4. 提交前检查几何、权限、单块/总面积与批量数量；问题定位到具体地块。
5. 提交异步任务，逐地块展示排队、执行、完成或失败；用户可以继续浏览地图。
6. 查看核查摘要，点击某项展开命中要素、相交范围、面积和规则说明。
7. 点击审批或供地记录查看来源系统成果；满足集成条件时携带项目/地块编号跳转。
8. 导出核查成果并保留任务快照，允许对失败项重试。

**完成标志：**每块地都有明确的检查状态、结果依据和缺失项；辅助核查结果不能被展示为正式审批意见。

### 5.3 时序变化对比：同一空间范围发生了什么变化

1. 选择区域或地块，再选择“影像、现状、规划”及两个或多个有效时相。
2. 系统展示可比版本及覆盖范围；用户选择卷帘、分屏或时间轴播放。
3. 地图视角同步，图例明确左右/前后时相，支持暂停和单期查看。
4. 对现状等可计算数据执行变化分析，生成新增、减少、转入/转出范围和统计表。
5. 点击变化记录定位，查看前后属性；关联审批/调查成果仅在存在业务关联时展示。
6. 输出对比图和变化表，标明分类标准、版本、统计范围及可比性说明。

**完成标志：**影像视觉变化与矢量计算结果明确区分，统计可回溯到参与比较的数据。

### 5.4 业务成果追溯：围绕一个项目或图斑查看业务进展

1. 进入生态修复、督察执法等专题，地图展示相应项目或问题图斑。
2. 按年度、类型、区域及来源状态筛选；地图和台账同时更新。
3. 选择对象查看空间范围、核心属性、阶段记录、关联材料和数据更新时间。
4. 点击阶段记录查看对应成果，必要时开启影像或边界对比。
5. 进入来源系统继续办理；返回后保留地图工作区，状态更新以来源系统同步结果为准。

**完成标志：**“对象—空间—阶段—成果—来源系统”可追溯。缺少关联编号时显示未关联，不以名称相近自动确定关系。

## 6. 详细功能需求

### 6.1 地图与资源能力

| ID | 功能及优先级 | 用户操作与业务规则 | 验收标准 |
| --- | --- | --- | --- |
| MAP-01 | 地图主工作区 P0 | 漫游、缩放、全图、框选缩放、方向复位、底图切换、图例、比例尺、坐标、鹰眼 | 切换底图保留图层与对象；定位后目标可见且不被面板遮挡 |
| MAP-02 | 区域定位 P0 | 自治区、盟市、旗县级联；区域名称检索与面包屑返回 | 选区后地图、摘要和台账范围一致；无授权区域不可查询 |
| MAP-03 | 四维图层目录 P0 | 按主题、部门、盟市、热点组织；分类数量、关键词检索、来源详情 | 同一图层多维出现仍使用同一资源ID；目录与命中计数有明确口径 |
| MAP-04 | 已加载图层 P0 | 可见性、排序、透明度、定位、收藏、移除、一键关闭；支持跨目录组合 | 调整顺序即时生效；一键关闭仅关显示；移除不删除源资源 |
| MAP-05 | 要素查询 P0 | 单点、穿透、多边形、拉框、周边查询；按图层分组展示 | 查询范围和图层集合在提交前可见；穿透可列出多个图层的命中对象 |
| MAP-06 | 统一检索 P0 | 搜区域、图层、地块/项目；工具与应用结果分类呈现 | 图层结果可加载，对象可定位，工具可执行或看详情，应用可打开 |
| MAP-07 | 量算与清理 P0 | 距离、面积量算；清除临时绘制、移除结果图层、恢复初始地图分开操作 | 临时量算不成为业务核查结论；清理操作不删除历史任务 |
| MAP-08 | 二三维与飞行 P1 | 二三维视图切换、方向控制、预设视点、飞行路线、暂停停止 | 有三维服务时保持兼容视点与图层；不支持的图层逐项提示 |
| MAP-09 | 地图方案与历史 P0 | 保存范围、专题、图层顺序/透明度、版本；查询历史快速定位 | 恢复时重新校验资源权限；失效项提示，不能悄悄换成其他版本 |

图层详情至少包含名称、业务含义、提供部门、发布时间、更新时间/更新频率、覆盖区域、时间版本、数据形态、可用操作和手册/说明。未登记字段显示“未登记”，不生成默认事实。

### 6.2 八类业务专题

每个专题采用统一模板：**业务问题、区域与时间、核心指标、关联图层、常用操作、结果台账、来源应用**。进入专题优先显示可执行工作，不把流程说明当成办理进度。

### 7.1 关键业务对象

| 对象 | 最小字段 | 主要关系 |
| --- | --- | --- |
| 地图工作区 | 工作区ID、区域、年份、视点、专题、图层配置、当前对象 | 联动所有面板 |
| 图层资源 | 资源ID、名称、主题、数源、版本、覆盖范围、坐标系、服务状态、权限 | 多目录共用同一资源 |
| 空间对象 | 对象ID、图层/版本ID、几何、业务类型、业务编号、来源系统 | 关联审批、供应、修复或执法成果 |
| 业务专题模板 | 模板ID、主题、默认图层、指标、动作、工具、应用 | 为当前范围组织业务能力 |
| 分析任务 | 任务ID、输入快照、子项、执行状态、规则版本、结果、执行人/时间 | 多地块、多核查项独立追踪 |

### 7.2 空间计算

1. 正式数据保留源坐标系标识，采用约定转换后叠加；未知坐标系拒绝计算。不得把 demo 的GCJ-02直接当作正式成果坐标。
2. 地块分析面积和相交面积使用约定投影/椭球算法；原业务登记面积与空间计算面积分字段显示，不能混用。
3. 比例默认是“相交面积÷该地块计算面积”；表头显式注明。显示面积建议两位小数，计算使用原始精度，极小非零值显示“＜0.01”并允许查精确值。
4. 同一核查项内重叠要素先做空间去重再汇总覆盖面积；不同核查项可能重叠，不能直接把八项面积相加作为总占用面积。
5. 边界接触但面积为零时标记“边界接触”；不得据此显示有面积占用。容差由正式数据精度规则配置。
6. 空间相交只证明范围关系；没有正式规则时不生成“合规/违法/准予审批”等行政结论。

### 7.3 统计与时间

- 业务指标默认按选定行政区或分析范围计算，地图视野变化不改变分母。
- 覆盖率等比率必须使用相应分子和分母聚合，不对盟市百分比简单平均。
- 目录数量按当前可见资源去重计数；父级计数为其子项资源并集，筛选时显示“命中数/可见总数”。
- 数据年份、更新时间、分析执行时间分别展示；跨年份核查逐项列出参与版本。
- 无记录且覆盖完整可显示0；缺数据、未登记、无权限、服务失败分别显示状态，不能统一填0。
- 容量统一单位并标明登记值/实时值。栅格图层数、栅格文件数和栅格容量，以及证照图层数和证照份数分别统计。
- 入口访问、查询请求、成功工具调用分开计量；一次任务的技术重试不重复计入业务成功调用。活跃用户依据所选事件口径去重。
- “累计/本月”注明统计起止时间；本月按Asia/Shanghai自然月计算。日期范围筛选用于区间卡片和趋势，避免与固定累计口径混淆。

## 8. 权限与异常处理

### 8.1 权限原则

读取、分析、导出、保存/分享分别授权，叠加用户角色、资源、行政/空间范围及有效期。目录可见不代表可读取内容；上级区划身份不自动获得全部下级数据权限。服务端执行与导出时重新校验，统计、搜索、缓存和历史恢复使用同一权限范围。

### 8.2 异常与边界

| 场景 | 用户可见反馈 | 系统行为 |
| --- | --- | --- |
| 部分图层加载失败 | 图层行标记失败和重试 | 其他图层继续工作，相关分析项标记不可用 |
| 必需核查数据缺失 | 提交前提示缺失项及影响 | 可执行可用项，但总结果为核查不完整 |
| 超单块面积/总面积/批量数量 | 具体地块、当前值、上限 | 阻止提交，允许修改输入；正式阈值由后台配置 |
| 几何跨出授权范围 | 标明超范围对象 | 拒绝分析，不静默裁切形成误导结果 |
| 提交后编辑草稿 | 提示新输入尚未分析 | 运行任务使用冻结快照；编辑副本生成新任务 |
| 切换区域后旧请求返回 | 无错误覆盖 | 旧结果不覆盖当前上下文，任务仍保留在历史 |
| 批量部分失败 | 显示成功/失败项及原因 | 可重试失败项，导出必须包含完整性说明 |
| 数据撤权或下架 | 历史/方案显示失效原因 | 禁止新调用，历史内容访问按当前权限处理 |
| 外部应用未配置/不可达 | 未接入/暂不可用，保留来源信息 | 不显示虚假办理成功或单点登录成功 |
| 底图不可用 | 提示底图异常并提供可用底图切换 | 已有业务结果不丢失，禁止伪装正常加载 |

| 可靠性 | 页面刷新可恢复已受理任务；服务失败可重试；重试不重复创建成果 |
| 审计 | 记录查询、分析、导出、跳转事件的用户、对象、范围、时间、结果及任务关联；保存期限由现有制度确定 |

正式交付依赖：行政区划和空间数据服务、元数据与版本服务、统计指标服务、分析计算服务、统一身份权限、工具/应用目录、业务对象关联接口、三维与多时相数据、运行遥测与成果文件服务。

具体地图引擎与框架在技术设计中确定，不能以 demo 的渲染实现替代正式空间计算。演示模式允许使用示例数据，但页面与导出均需显著标识；接入缺失不等于需求已通过验收。
