## 2. 合并后的产品定位

综合集成是面向自然资源工作者的统一入口与认证基座，通过“统一认证、三域集成”承载三类主要使用体验：

| 使用面 | 主要用户 | 用户要完成的事 | 对应范围 |
| --- | --- | --- | --- |
| 后台：一张图成果工作区 | 管理层、空间业务人员 | 看图、查地块、做分析、看资源使用与接入情况、打开工具和场景 | 附表 1.1.1；正文 5.4.1.1.1.1 |
| 数字资源门户 | 业务人员、开发人员 | 综合搜索、了解资源、查看动态、批量申请、调用与订阅 | 附表 1.1.2；正文 5.4.1.1.1.2 |
| 个人工作门户 | 内部业务人员 | 看待办和提醒、进入办理、使用收藏应用与工具、配置个人桌面 | 附表 1.1.3；正文 5.4.1.1.1.3 |
| 配置与接入后台 | 门户运营、集成管理员、租户管理员 | 配置门户、统一认证、系统对接、交换任务、权限与监测 | 附表 1.1.4—1.1.8；正文 5.4.1.1.1.4 |

当前设计的主要偏差：把综合集成压缩成了“资源总览、系统接入、集成待办、纵向节点、同步记录”五个页签，缺少成果、资源、个人工作三个使用域的完整组织，也缺少对应配置管理。后续应按使用场景建立页面，再映射八类需求；不能只把八个章节名称做成八个空页签。

另一个边界问题：本正文描述的内部综合门户不能直接等同于现有面向公众的门户。已有公共门户图片、资讯和导航可以复用组件，但发布渠道、访问人群及展示配置必须明确区分。

## 4. 正文细化后必须补入设计的内容

### 4.1 成果集成不是一个资源卡片列表

**空间图层目录与查询**：主题、部门、盟市、热点四个分类维度及层级数量；图层检索定位；单点、穿透、多边形、拉框、周边五类要素查询。查询必须使用与当前图层一致的数据及权限，不能仅返回静态说明。

**二三维交互**：漫游、方向切换、全图、缩放、拉框缩放、底图切换、地图清空、鸟瞰、飞行、收藏、透明度、一键关闭图层、测量、图例。现有 OpenLayers 的显示隐藏、透明度、底图和测量等能力应复用；二维运行不能标记成三维能力已完成。

**三维通用分析**：日照、通视、可视域、天际线、控高、视廊管控、坡度坡向。需要真实高程/地形/建筑模型、坐标和高程基准以及对应算法。不能以二维面积或缓冲区功能替代。具体数据源、精度、算法及执行引擎属后续技术设计与联调条件。

**五组专题能力**：

| 子需求 | 合并后的范围 | 原型设计要求 |
| --- | --- | --- |
| 时序查询展示 | 多年影像、现状、土地规划，时间轴或动态图层对比 | 建立同主题不同时期数据的关联，展示时间、版本和无数据状态 |
| 本地专项分析 | 规划地类、建设用地管制区、农转用审批、土地供应、永久基本农田、生态红线、自然保护地、水源地保护区 | 明确每个专题的输入、图层、查询/计算规则与结果钻取；已有示例三图层核查不能视为八专题完成 |
| 定位与历史 | 查询历史定位及省/市/县行政区定位 | 历史关联查询条件、范围、图层版本和操作者；已有异步作业历史仅为可复用基础 |
| 权限与面积限制 | 按用户层级限制数据和功能，绘制面积阈值预警/限制 | 服务端复核权限与计算面积；现有文件大小、地块数量限制不能替代业务面积阈值 |
| 异步与批量 | 多地块分析、异步执行、每地块进度与结果 | 复用现有作业机制，补逐地块状态和专题数据依赖；失败需说明具体原因 |

### 4.2 三类集成监测需要业务指标，不能由主机监控代替

| 监测对象 | 正文明确的指标和维度 | 数据来源设计建议 |
| --- | --- | --- |
| 图层资源规模 | 总容量、矢量图层数、数据表数、栅格数据量、证照数据量 | 资产元数据及存储统计；没有容量采集时显示“未采集”，不能填0冒充真实容量 |
| 数据汇聚 | 厅内/厅外部门、已接入数量、接入进度与状态 | 部门台账、接入计划、归集/发布结果；完成率须有明确计划分母 |
| 数据共享 | 累计调用、本月调用、活跃用户；时间/部门/资源维度 | 实际数据服务调用事件，区分成功、失败、调用者及部门 |
| 热门图层 | 图层实际调用次数排名、详情、来源、更新频率、权限 | 同一图层主ID归集调用记录，不能用资源申请数替代 |
| 工具总览与接入 | 工具总数、对接部门数、类别分布、部门数量及占比 | 工具台账、提供部门、类别、接入状态 |
| 工具调用 | 累计、本月、累计使用人数，日/周/月趋势 | 实际调用日志；外部入口打开和工具执行分开统计 |
| 工具双排行 | 按工具调用次数、按调用部门总调用量 | 以调用事件及调用时部门快照汇总 |
| 场景总览与接入 | 场景数、部门覆盖、部门场景数及占比、场景使用情况 | 场景/应用台账和进入/使用事件，防止一场景多个入口重复计数 |

正文规定以卡片、图表展示，并特别提出工具分类饼图、调用排行柱图。后续原型应同时提供统计口径、时间筛选和可下钻明细，不能只做数字卡片。

### 4.3 场景主题与现有系统归口

统一保留正文八类主题：自然资源“大管家”、国土空间规划、耕地保护和国土绿化空间、要素保障、矿产资源、生态修复、督察执法、灾害防治。正文个别位置写“督查执法”，本分析统一标签为“督察执法”，正式字典仍需业务确认。

八类是展示目录，不表示八类场景都由本项目新建。正文明确快速访问五类新建场景及归口的现有系统；需要分别记录“主题类别、场景对象、业务应用、来源系统、访问入口”，不能把九系统台账直接当成九个场景。

工具和场景详情均需补齐类型、发布单位、发布时间、提供方、介绍和使用手册。应用现有图标/截图可以复用，但不能以截图代替手册和正式发布信息。

### 4.4 数字资源门户与配置要联动

- 综合搜索结果覆盖数据、服务、工具、知识、智能体、应用场景；每条结果应到对应对象详情，再进入有权限的使用或申请流程。
- 搜索热词依据实际访问和搜索事件动态推荐，一般不超过5个。未采集时使用明确标注的推荐词或空状态，不能称为“热门”。
- 五中心导航按用户可访问权限呈现；运营中心是管理入口，不应向普通用户开放后台操作。
- 资源动态与热门资源区分“上新发布事件”和“使用热度”；图片、视频、文字是内容展示类型。
- 宣传区、Banner、快捷导航、核心优势与公告应通过内部门户配置发布后生效，而非只存后台表单。

正文额外明确的核心展示字段：

| 配置对象 | 必须覆盖的字段/行为 |
| --- | --- |
| Banner | 图片、标题、副标题、导航栏字体颜色、按钮；新增、编辑、删除 |
| 快捷导航 | 图片、标题、链接地址、简介；新增、编辑、删除 |
| 核心优势 | 图标、标题、简介；管理展示内容 |
| 公告 | 内容、显示时效、弹窗样式、推送范围 |
| 基础外观 | 顶部导航、二级入口、主题、背景图、公告轮播 |

建议增加草稿、预览、发布和版本回滚，防止编辑即影响全体使用人。这是实现建议，原文没有明确规定版本流程。

### 4.5 任务、消息和公告应统一模型、分别管理状态

业务任务记录办理状态；消息记录送达和已读状态；公告记录发布窗口和目标人群。阅读消息不能自动把任务变成已办，关闭弹窗也不能代表业务办理完成。

建议共用一套通知来源适配与收件箱：系统通知、审批消息、任务进度、资源/应用上新。前台在任务中心、消息列表、红点和弹窗呈现同一数据，避免分别维护多个消息表导致数量不一致。

“我的应用”使用个人收藏清单；最近访问可以另设分区。“我的工具”同理。已有统一收藏应扩展类型视图和分组排序，不另建一套互不一致的收藏。

个人配置分四组，并明确生效点：

| 配置 | 运行时效果 |
| --- | --- |
| 工作台 | 应用/工具分组、顺序、显示模块按用户恢复 |
| 任务办理 | 待办/已办/预警列表与提醒方式发生实际变化 |
| 业务看板 | 所选指标按已授权数据源、配置频率刷新，显示统计时间与失败状态 |
| 消息 | 开关、接收方式、免打扰窗口影响提示；建议静默保留站内记录，具体强制提醒例外属设计规则 |

### 4.6 外部接入与三级租户必须分开验收

内部九系统、国家节点、自治区横向平台需要各自的接入合同和适配配置。建议统一接入对象，但保留对接类型、身份方式、资源交换方向、待办映射、接口版本、联调结果与联系人。

“配置完整”“本地模拟通过”“外部联通”“业务验收通过”应为不同状态。JSON导入是本地交换能力；不证明自动同步、单点登录或跨系统办理已完成。

三级租户是安全与资源边界：

- 节点代表交换端点，组织代表行政/部门关系，租户代表独立管理空间，三者需要关联但不能混成一个对象。
- 上级可创建和管理下级租户；下级权限不能超过上级授予范围。
- 资源、成员、角色、功能和授权必须带租户边界，服务端查询和写入均校验；仅前端隐藏无效。
- 下级停用、人员迁移、上级收回权限后的授权和任务影响，需要在实现设计中明确。
- 如果先实现独立租户原型空间而尚未约束全平台数据，应明确标注该边界，不能称为已完成平台级租户隔离。

## 5. 推荐的信息架构与管理归属

### 5.1 前台页面

1. **综合门户首页**：综合搜索、实际热词、六类统计、五中心导航、宣传、动态、热门资源。
2. **成果工作区**：图层目录与地图、查询与专题分析、工具箱、八类场景入口；授权用户可进入监测看板。
3. **个人工作台**：任务概览、待办/已办/预警、收藏应用、收藏工具、消息、更新通知、个人配置。

三个使用面复用同一资源ID、应用ID、工具ID和权限。可以通过页面或工作区切换实现，无需为了章节编号拆成独立系统。

### 5.2 后台页面分组

| 管理分组 | 建议页面 | 与其他中心的关系 |
| --- | --- | --- |
| 门户展示管理 | 基础外观、Banner、导航、核心优势、宣传、资源动态、公告 | 管理展示与发布，不复制资源主数据 |
| 成果集成管理 | 图层/工具/场景关联目录、八类主题、归口系统、展示顺序 | 图层主记录复用资源管理，工具注册审核复用工具中心，场景构建复用应用中心 |
| 工作集成管理 | 待办来源、字段映射、状态映射、同步策略、异常任务、通知规则 | 办理流转保留在来源系统或本地流程模块；统一呈现 |
| 集成监测 | 图层、工具、场景总览及接入、共享、调用排行 | 复用运营中心采集和日志；此处提供业务视角 |
| 身份与系统接入 | 认证客户端、账号映射、九系统台账、会话、用户同步、联调日志 | 复用统一身份与权限底座 |
| 国家节点对接 | 命名域名、国家基础服务订阅、本地图层注册、部区身份对接 | 承载国家对接规范及业务状态 |
| 纵向贯通 | 节点、交换目录、同步任务、三级租户、成员、授权模板 | 节点交换与租户隔离分开管理 |
| 横向联动 | 数据局/政务平台等接入、用户与服务映射、交换任务、异常重试 | 复用通用接入任务与日志，不复制一套调度系统 |

### 5.3 唯一管理归属

| 对象/行为 | 主管理位置 | 综合集成负责 |
| --- | --- | --- |
| 数据归集、质检、技术发布、基础运行监控 | 运营中心 | 读取接入/发布/监测结果与提供定位入口 |
| 资源共享策略、申请、授权、交付 | 资源中心及统一资源台账 | 统一发现、申请入口及使用状态汇聚 |
| 工具注册、审核、版本与下架 | 工具中心 | 目录、快捷访问、收藏与集成使用监测 |
| 场景构建、应用注册与上架 | 应用中心 | 主题分类、归口入口、使用与接入总览 |
| 智能体和知识能力 | 智能中心 | 可见资源检索与授权入口 |
| 门户外观、宣传、公告、个人工作入口 | 综合集成 | 配置与运行展示闭环 |
| 身份、组织、角色及审计 | 统一平台底座 | 客户端接入与上下级/横向身份对接 |

## 6. 实现建议：对象、闭环与验收

以下是为落地需求提出的设计建议，不作为原文新增功能条目。

### 6.1 核心对象

- **统一资源索引**：资源类型、主对象ID、名称、版本、发布单位、提供方、主题、行政区、来源、详情入口、申请/使用策略。
- **图层/专题关系**：图层ID、主题、部门、地区、年份、数据版本、坐标基准、服务类型、来源与适用范围。
- **展示配置版本**：发布渠道、页面区域、素材、排序、可见范围、草稿/发布版本。
- **搜索及调用事件**：时间、事件类型、资源/工具/场景ID、用户、调用时部门、租户、成功状态、耗时、追踪ID。
- **统一任务映射**：来源系统、来源任务ID、名称、发起时间、截止时间、处理人、业务状态、预警状态、办理入口、同步时间。
- **通知与公告**：来源事件、目标人群、窗口、展示方式、投递状态、已读/确认记录；同一事件重复同步需幂等。
- **个人偏好**：用户、收藏分组、排序、展示状态、指标数据源、刷新频率、通知渠道、免打扰时段。
- **接入与交换任务**：对接类型、端点、协议、映射、方向、游标、执行状态、成功/失败明细、重试与日志。
- **租户与委派授权**：父租户、区划、成员、角色、资源归属、上级授权模板、有效期、下级分配边界。

### 6.2 必须跑通的端到端流程

| 流程 | 最低可检验结果 |
| --- | --- |
| 门户编辑→预览→发布→用户访问 | 发布前草稿不改变运行页面，发布后对应Banner/导航/公告实际更新，超期内容退出展示 |
| 资源发布→索引更新→检索→申请→授权使用 | 结果到具体资源；可发现不代表可调用；下架及撤权后入口/服务同步受限 |
| 来源待办→同步→提醒→穿透办理→状态回传 | 重复事件不产生重复任务；已读不等于已办；同步失败有可定位原因 |
| 工具/场景接入→归类→访问/调用→监测 | 接入数、部门覆盖、成功调用与入口访问口径分开，排行可追溯到事件 |
| 图层选择→权限检查→分析→历史复查 | 无权图层不参与计算，缺失数据不返回“无冲突”，历史带参数与数据版本 |
| 上级租户授权→下级分配→访问→上级撤回 | 下级不能越权扩大范围，直接API访问同样被拦截，收回授权后不能继续读取 |
| 国家/横向配置→实际联调→交换→回执 | 配置校验与真实传输状态区分；失败任务保留明细并支持受控重试 |

### 6.3 实施次序

| 顺序 | 工作 | 完成判断 |
| --- | --- | --- |
| 第一批：需求与结构 | 固定40项追踪、三个使用域的页面归属与配置管理分组、复用对象、统一统计/状态口径 | 每条有入口、归属、状态、验证方式，当前文档作为初始基线 |
| 第二批：本地可执行门户 | 综合首页、六类统计与搜索、动态/热词、收藏应用/工具、公告、个人配置、展示发布 | 配置真实生效；统计来自事件；通知遵循个人设置；不依赖外部系统即可验收 |
| 第三批：成果与监测 | 复用二维地图与异步核查，补图层分类、专题关联、八类场景、三类集成监测 | 页面可下钻到数据和日志，权限和版本正确；专项分析按真实数据覆盖逐项验收 |
| 第四批：协同与隔离 | 待办适配任务、节点交换、租户与分级权限、国家/横向管理 | 本地适配测试通过且权限有服务端隔离，外部尚未联通的任务保持明确待联调 |
| 专项联调：外部与三维 | 真实SSO/MFA、九系统、国家/横向接口、二三维引擎和专项数据 | 使用正式SDK/接口/数据执行验收；不能以示例导入或二维结果代替 |

真实接口联调与三维数据准备可提前并行开展，不应等到所有本地页面完成后才确认依赖。

## 7. 尚需明确的设计输入

这些问题不阻塞门户基础功能，但不能通过随意造数据来掩盖：

- 国家SDK、基础服务清单与注册协议，自治区横向平台的交换规范和认证方式。
- 两个待办系统的接口、状态字典、用户标识映射、办理回传能力与实时性指标。
- 三维地形、建筑模型、高程基准、可用引擎及七类分析的精度和性能要求。
- 八类专题的正式图层、年份、覆盖范围、计算规则以及业务面积阈值。
- 资源容量与证照/栅格数据量的单位、计数对象；接入计划分母、活跃用户和调用统计窗口。
- 部门接入统计按提供部门计数，调用排行按使用部门计数；二者不得混用。
- 租户是否只托管新建空间，还是需要约束现有所有模块；正式交付需明确隔离范围。
- 公告推送范围、强制通知例外、免打扰策略，以及个人设置与岗位默认设置的优先关系。
